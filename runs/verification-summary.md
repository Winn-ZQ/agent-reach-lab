# 第一阶段复核循环验收

本记录区分真实报告与人工错误测试，不提供准确率估计。

## 真实报告

输入：第一次通过 Exa 搜索、Agent-Reach/Jina 读取的通力官网原文及主助手报告。

独立子助手检查 7 项核心结论与元数据，未发现实质问题；控制器将 `runs/kone-review` 标记为 `passed`，修正次数为 0。通过只代表报告与保存原文相符，未验证厂商实际效果或资料完整性。

## 人工错误测试

在另一个明确标注的副本中加入三个错误，不修改真实报告：

| 注入错误 | 子助手指出的问题 | 主助手采取动作 |
| --- | --- | --- |
| 所有故障可远程修复 | 原文保留现场处理 | 改为远程与现场协作 |
| 全球所有型号和合同功能相同 | 原文有设备、合同、市场限制 | 恢复适用范围限制 |
| 采集日期就是发布日期 | published_at 为空 | 标记发布日期未确认 |

实际链路：初稿 → 独立复核要求修改 → 控制器进入 needs_revision → 主助手修正 → 第二次独立复核通过 → 控制器进入 passed。

修正次数为 1，上限为 2。原文足以修正，因此没有重新搜索，也没有验证补查分支。

第二次复核期间曾遇到子助手用量限制，流程没有将错误当作通过，也没有增加修正次数。用户要求继续后完成复核并提交状态；这是宿主助手恢复执行，并非 Python 内置自动恢复。

## 程序测试

`python -m unittest -v test_loop.py` 的 6 项测试全部通过：通过后停止、达到修正上限转人工、拒绝过期复核、拒绝带问题的通过结论、拒绝无实际变化的修正、拒绝被改动的存档。

## 已完成与剩余工作

已实现由当前助手驱动的真实子助手复核与一次反馈修正循环，并用程序记录版本及限制次数。`loop.py` 不调用模型，不会独立运行子助手。

尚未验证：多个真实问题的质量、补查新证据分支、模型费用与耗时对比、小红书渠道、独立应用运行。当前结论不支持“90%准确率”或“优于通用 Agent”。

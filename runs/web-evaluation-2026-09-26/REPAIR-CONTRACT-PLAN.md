# 逐项修正契约验证

本轮改动是交接机制，不再只增加提示词：每个复核问题获得程序编号，模型提交指定目标的补丁及带原文依据的处理回执；程序拒绝漏项、错目标、只改引用或空白却声称改正文。允许举证反对错误复核意见。再复核逐问题判断是否解决，未解决不能通过。

保留旧任务与额度台账。按用户动态预算授权，开发日上限36→44，用于最多3次已知缺陷修正回归及最多5次新题验证；实际调用另记，不清除旧未知用量。仍仅使用有免费保护的模型，不充值。

## 两步验证

1. **已知问题修正**：沿用Notion3份证据和上轮最终草稿。Q3沿用模型阻断意见，Q4由本助手根据已确认的“设置与数据混淆”补充开发评审标注；该标注不是独立模型发现。先Qwen补丁，再DeepSeek独立复核，必要时只允许原程序的一次格式修正，最多3次。单独记录是否改对，不能把人工指出的缺陷声称为系统自动发现。
2. **新任务验证**：第一步成功才执行一个未用于上述提示调优的公开网页问题，沿原网页调度器获取、分析、复核及有限修正，最多5次。不把一次新题通过称为泛化准确率。若第一步失败，停止追加模型调用并记录具体机制问题。

两步均保留真实输入、响应、哈希及用量于本机。流式仅作为开发验证配置，正常网页仍用JSON默认。程序测试与语义结果分开报告。

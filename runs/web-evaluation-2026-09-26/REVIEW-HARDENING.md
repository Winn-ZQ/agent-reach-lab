# 复核依据与修正闭环收紧

2026-09-26。承接 Notion 跟进任务暴露的复核误读和修正不彻底问题；本轮没有增加平台、模型或调用预算。

## 已实现

- 新真实复核使用 `research-review/0.2`：每项声明所依据的来源都必须附连续原文。引用不存在、引用排除来源、来源列表与引文不一致会使复核无效，不能自动据此修改草稿或标记通过。
- 复核问题关联具体答案/假设目标。阻断意见与同一目标的“支持”判断不能自相矛盾；不受支持的目标必须有问题说明。
- 合理未知和草稿逻辑判断允许没有来源引文，不强迫模型编造证据。原文匹配仍不代表语义成立，也不能证明“不存在其他说明”。
- 修正提示要求核实复核意见，修改标题、列表分类和因果关系；不可只换词。再复核收到旧稿及旧问题，同时明确旧意见可能错误，必须重新核对原文。
- 页面“过程与复核”的逐项检查可显示复核原文及来源入口。历史复核按旧契约读取，不补造原文、不改旧结论。
- 网络诊断补充 TLS 提前关闭的固定分类；页面用中文显示请求阶段。没有关闭证书校验、绕过代理设置或自动重发未知用量请求。

## 验证

全套 **134 项程序测试通过**；JavaScript 语法和 Git 差异检查通过。新增测试覆盖虚构表格引文、缺少来源依据、阻断意见矛盾、未知判断、真实契约执行路径以及再复核的前后版本绑定。测试使用预设传输，不读取真实密钥、不产生模型调用；历史夹具继续按旧格式验证。

进行了3次不带授权头的 HTTPS HEAD 检查，使用与模型传输相同的 urllib / 默认 TLS 校验和禁止重定向机制，目标为百炼通用接口。耗时分别7.058、10.813、2.974秒；前两次记录TLS错误，最后一次收到HTTP 400。HEAD请求没有模型请求体或密钥，未调用模型。该结果显示检查时连接存在不稳定，不能定位到供应商或中间网络，也不能代替模型POST验收。

Python当前未发现显式代理路由；这不排除VPN、透明代理或其他网络设备。没有自动修改本机网络设置。

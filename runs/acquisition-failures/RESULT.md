# 获取失败处理验收

日期：2026-09-23。范围：单个网页来源的失败处理，没有测试小红书登录。

## 真实联网结果

使用明确构造的测试地址 `https://example.com/agent-reach-missing-page-20260923`，不是用户业务页面。

- 沙箱内首次访问出现 network_error，记录在 live-missing.json，未将其解释为站点不可用。
- 批准联网后通过 Agent-Reach/Jina 访问，获得并识别 not_found，记录在 live-missing-network-enabled.json。
- 仅一次尝试即停止；正文为空、没有有效证据哈希，输出“未取得该来源的有效正文，不能据此生成事实结论”。

这是实际联网访问测试路径得到的错误，不是模拟 HTTP 响应。业务网站故障行为仍需分别验证。

## 模拟测试（不属于真实平台故障）

| 情况 | 行为 | 记录 |
| --- | --- | --- |
| 连续超时 | 总共2次尝试后停止 | timeout_exhausted.json |
| 超时后成功 | 第2次成功，保留失败尝试历史 | timeout_recovery.json |
| 登录页面 | needs_user，不自动重试、不记录登录正文 | login_required.json |
| Jina包装的目标404 | not_found，不当成有效资料 | wrapped_404.json |

其他自动化检查覆盖HTTP 401/403/410/429/503、空内容、未知异常及失败证据不能进入分析。与已有循环和证据包测试合计16项全部通过。

## 停止规则

- 超时、408及部分5xx：默认重试1次，参数上限2次；底层每次请求超时30秒。
- 401/403或明显登录/验证页：停止，提示用户在本机确认访问条件。403不直接等于未登录。
- 404/410：停止，核对链接。
- 429：停止，稍后再试，本轮不自动等待重试。
- 网络/DNS问题：停止检查环境，不根据它判断业务内容不存在。
- 全部失败：本来源不给事实结论。若有其他有效来源，是否足以回答仍由主助手和复核判断；没有新增跨来源自动调度程序。

## 边界

仅能识别明确HTTP错误、Jina错误头和少量高置信度标题，不能保证识别所有软404、定制登录页或返回200的反爬页。其余获取结果继续标记 fetched_unverified，需复核正文。重试与报告修正分别计数，不能把网络重试当作Agent分析循环。

错误记录使用分类和通用说明，不直接保存异常中的潜在凭据；输入URL本身仍会被保存，公开发布前应检查链接中的敏感参数。未自动读取密码、Cookie或执行登录。

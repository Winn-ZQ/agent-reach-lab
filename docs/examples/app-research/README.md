# App 研究交付样例

先打开 [结果页面](index.html)，切换三种状态，点击结论下的“查看支持片段”，再下载对应 Markdown 和 CSV。双击 HTML 即可本机打开，不需要 API 或登录。

**全部 App A 内容均为人工构造的演示数据，包括官网说明、笔记、作者、日期和复核结果。没有采集小红书，没有模型 API 调用。** 样例用于判断报告是否有用以及交付字段是否足够，不证明产品已经实现或有效。

## 同一份内容，三个展示状态

| 状态 | 展示内容 | 不能误读为 |
| --- | --- | --- |
| 完整报告样式 | 功能、样本表达、反例、两个改进假设、验证动作及来源 | 全部问题均已回答；总体发生率依然未知 |
| 小红书来源缺失 | 仅网页说明、缺失问题及下一步；无反馈假设 | 没搜到反馈等于没人抱怨 |
| 复核服务失败 | 同一初稿保留，页面和导出都标为未复核 | passed；此状态仅模拟超时，不是实际 API 故障测试 |

`result.json` 是唯一内容源，生成三个 Markdown、六个 CSV、一个 HTML。网页切换仅切换已经生成的展示，完全不联网。当前没有“重试复核”的实际按钮，以免把样例交互误当后台执行。

## CSV 如何继续使用

- `*-items.csv`：一行一个结论或假设。可按“类型”筛选改进假设，再看观察、其他解释、证据ID、下一步验证、判定依据。负责人和计划日期留空，供研究者在表格软件中填写。
- `*-sources.csv`：一行一个来源，包含原文片段、定位、日期依据、是否纳入及排除理由。证据ID用英文分号分隔，与来源ID关联。
- 每行保留演示标识、稿件和复核状态。空 URL 表示没有真实链接；空日期表示未知，不是零或采集日。不能把这些虚构条目导入真实调研统计。
- UTF-8 BOM、引号转义与换行遵循 CSV 形式；导出文本前检测可被表格软件执行为公式的前缀并加单引号。本样例不要求 CSV 保留表格样式，也不提供 XLSX。
- 修改导出的 CSV 不会回写后台或自动变成已复核结论。负责人和计划日期只是后续整理字段。

## 输入、输出与责任

1. 产品经理输入研究问题与范围。本例固定四个子问题，避免事后改变覆盖率分母。
2. 目标产品的获取适配层提供实际来源与取样日志；本例这些资料由人工虚构，`sampling.executed=false`。
3. 目标产品的分析模型形成结论和假设，复核模型独立检查；本例内容和复核状态都是人工设定，没有调用模型。
4. 生成器把同一结构化结果映射成网页、Markdown、CSV。此步骤已实际执行，无需模型。
5. 研究者查看证据与反例，选择下一步验证，之后才考虑真实开发优先级。

真实历史材料另见 [KONE 本地来源核对](real-evidence-check.md)。该核对只证明已有本地原文中的片段与记录一致，不证明 App A 样例真实或新后台已实现。

## 实现边界

这是可打开、可切换和可下载的结果页评审样例，不是正式本机网页应用。已有原型代码未因本次文档修改而获得新的预算调度、任务恢复、模型 API 或小红书能力。目标规则以 [PRD v0.2](../../PRD-v0.2.md) 为准。

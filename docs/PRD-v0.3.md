## 1. 这次变更的性质

整体方向不变：面向产品经理／个人研究者，根据意图选取外部资料，整合分析，经独立复核与有限修正后交付回答或资料包。采用本机网页＋模型 API，Agent-Reach 的资料获取能力通过可替换组件接入。

本次确定的是产品的信息架构、主要操作方式和多来源扩展规则。逐步覆盖 Agent-Reach 支持的资料获取路径本来就是长期方向；这次提前为其安排界面与能力边界，不把全部平台加入当前阶段验收。

长期覆盖指适用于研究的搜索、读取、详情、评论、字幕、转录等获取操作。发帖、评论发布、仓库写入等写操作不纳入当前产品承诺；定时监测也不因支持 RSS 读取而自动成立。上游新增能力不自动安装或授权，不承诺所有能力同时可用或固定完成日期。

## 4. 来源中心与任务范围

### 4.1 全局能力目录

目录按网页与订阅、社区与社交、视频与音频、代码与项目、职业与企业、财经社区组织。支持按平台和操作名称搜索，如“字幕”。分类用于导航，不决定调用权限。

明确分开“上游支持目录”和“本机已接入能力”。以具体操作展示未接入、待配置、需登录、已安装未验证、最近验证可用、部分可用、暂时失败，附最近验证时间及失败原因。笔记可读不代表评论可读，视频信息可读不代表字幕可得。

用户可以表达对未接入来源的需求，但它必须标记不可执行；界面不得把勾选变成连接成功。后端只执行已注册、已授权、通过必要检查且预算允许的操作。

### 4.2 单任务选择

- 自动匹配：在可用能力中按问题选择，用户明确指定的平台/内容类型作为约束保留；不能将不可用指定来源悄悄删除。
- 指定来源：用户限定平台、必要操作或链接；可查看时间、地区、数量与预算范围。
- 必需来源：缺失会影响任务成立，例如“只看小红书评论”；失败时保存已有证据并进入待处理状态，不正常交付完整报告。
- 可选来源：可在预算内尝试；失败保留原因并继续可成立的部分，在页面和导出中同步披露缺口。

登录由用户在本机完成，重新检查后才能恢复失败步骤；不要求聊天粘贴密码或 Cookie。改变必需来源、实体、地区或时间范围沿用 v0.2 第19.4节：已开始获取后创建关联任务，保留旧证据、旧报告和原消耗。仅跳过原本可选来源可留在当前任务。原型中的就地改范围是演示简化，不是生产恢复规则。

### 4.3 自动执行与预算

正式页面按后端事件展示获取、分析、复核、必要修正及停止原因，不用计时器冒充真实进度。正常阶段之间不要求用户点击继续；涉及既有授权外的动作按原规则处理。

各平台共享单任务搜索、读取、来源量、模型调用、token 和活动时间上限；不因新增平台复制额度。追加资料前保留必要分析和复核预算。用户已授权由助手把控合理调用规模，无需每个调用重新询问；额度不足时告知，不自动充值，不重置历史台账。这不取消产品对每个任务的可见预算与程序限额。

## 5. 资料与交付契约

沿用 v0.2 的 Source、EvidenceChunk、EvidenceSet、Claim、Draft 和 Review 版本绑定。各来源统一包含平台、内容类型、URL、采集时间、发布日期及其可信程度、取得范围、失败/截断信息与引用定位。

按类型扩展，而非为每个平台复制报告页：

| 类型 | 必要扩展 | 不可越界的表述 |
| --- | --- | --- |
| 网页 | 发布主体、正文片段定位 | 官网描述不等于独立事实验证 |
| 笔记与评论 | 所属关系、作者去重、查询/排序/采样记录 | 样本观点不等于市场占比，笔记不冒充评论 |
| 视频字幕/音频转录 | 时间位置、语言、覆盖范围、取得方式 | 有文本不等于看过画面或完整听过音频 |
| 代码与项目 | 仓库、文件、版本或提交定位 | 当前页面不代表全部历史版本 |
| RSS 条目 | 条目身份、发布/采集时间、原链接 | 读取一次不等于持续监测 |

报告区按来源及类型查看资料，区分官方事实、用户观点、分析推断和改进假设。回答、资料包、Markdown 和 CSV 由同一份结构化结果生成，缺失来源和复核状态保持一致。取样及质量门槛继续采用 v0.2 第5、12、24节，不编造准确率目标或复核收益。

## 6. 扩展方式与前后端边界

正式后端能力注册表至少记录平台、操作、适配器版本、输入/输出类型、授权条件、健康检查和限制。前端读取脱敏能力与状态，不保存密钥，不直接执行平台命令；模型只提出注册表允许的操作，程序负责权限、预算和参数校验。

新增来源的验收顺序：确认适配器及授权要求 → 验证目标操作 → 转换统一证据 → 测试失败/缺失分支 → 在来源中心标记实际状态 → 用真实任务验收报告与导出。

原型的 `catalog.js` 只是展示目录，不能作为可信执行白名单或实际安装清单。2026-09-26 实施版增加后端来源目录及仅网页可执行的约束，并复用模型角色路由；多平台操作级健康探测与适配仍待开发。没有升级 Agent-Reach 或安装新平台。

### 下一轮验收：A 的网页研究流程

1. 提交问题后自动获取、准备证据、分析、复核，在预算内按条件修正；没有逐阶段继续按钮。
2. 正式界面与模拟草稿有明确区别；后台状态、来源数、模型调用和停止原因如实显示。
3. 未接入必需来源会阻断；可选来源失败不丢弃成功证据，缺口随页面与导出保留。
4. 引用能打开对应版本原文；页面与 Markdown/CSV 共用结构化结果，未通过稿不显示通过。模型选择来源与连续原文后，程序在严格校验通过的前提下填写来源已有的定位标签；原稿和绑定前后哈希均保留，程序绑定不等于语义复核通过。
5. 取消、预算不足、刷新和必要用户处理保持既有状态/账本规则；不能静默重放调用。引用失败最多创建一次复用证据的关联修正，新任务独立记账，旧证据与草稿须核验哈希；修正仍失败则停止。
6. 来源中心增删展示条目不改变主导航，不使未授权操作可执行。

上述为待验收要求，原型浏览器检查不算真实后端验收。当前轮只接已有网页能力，不以实现全部平台、移动端完整优化或重新选择模型作为完成条件。之后接通小红书，再按真实需求逐个验收其他来源。

### 验收阶段预算修订（2026-09-26）

用户授权根据阶段合理调整。新研究按完整流程预留最多5次（分析、一次格式修复、复核、一次内容修正、再复核），已有复核意见的关联修正/连接恢复为2次，引用修正任务最多4次。每日基础12次，按提交任务需要以4次为步长增加，硬上限24次；额度充足时自动发放并将调整原因写入本机分配记录，不要求用户逐次批准。所需阶段容量不足时不拆散流程派发。完成后按实际调用结算并释放未用名额；在途及用量未知保留预留。至少预留分析和复核所需2次；每日按任务发起日UTC归属。Token与免费额度独立约束，保留用完即停、不自动充值。策略修改不清空已发生消耗，旧记录必须依据真实请求日志结算。

复核已要求修改但本轮预算不足时：仅在未执行内容修正、无需补来源的条件下创建一次关联修正，沿用哈希绑定的证据／草稿／复核意见，执行修正＋再复核。历史复核明确标识，不重复计费或冒充新复核；不允许对关联任务继续套用，避免无限循环。


### 开发验收配置与正式使用规划（2026-09-26，用户确认）

当前3页来源、新研究5次模型请求、每日基础12次至硬上限24次等规则，统一命名为“开发验收配置”。它实际约束当前本机网页的运行，不只是开发助手的操作约定。界面在提交区和运行设置中明确标注；目前只有这一套执行配置，尚未实现配置切换。

正式使用阶段规划：

- 提供“快速研究／标准研究”等任务档位，按研究范围分配资料量和调用容量；具体数值由多题质量、耗时及成本评测确定，不直接沿用验收阈值。
- 提供用户可设置的日费用上限。启用前需落实供应商价格、币种、输入/输出与缓存计费规则及价格版本，区分预估费用、接口用量和实际账单；不能把调用次数或免费Token额度称为金额上限。
- 配置和价格版本应绑定新任务；改变档位或日费用上限不重置旧消耗、不追溯更改进行中的任务。仍在追加获取和调用前为必要分析、复核预留容量，失败或未知用量保留占用。
- 付费使用需要另行配置与授权，不由开发验收模式自动转为付费；所有档位保持有限修正、证据追溯和真实复核状态。

以上属于后续产品化规划，不是当前已实现功能，也不增加本轮界面/GitHub收尾的验收阻塞项。


### 缺陷验证阶段补充（2026-09-26）

两题实测暴露整句问题归为Q1会掩盖细项遗漏。新任务按明确问句/疑问从句生成逐项清单，保留完整任务，不额外调用模型；分析与复核逐项响应，页面展示清单及覆盖计数。这只是确定性拆分，不能宣传为已覆盖所有隐含要求；旧证据包保持原哈希。固定类别的连接诊断补充失败阶段，不输出异常原文，不把用量未知改为零。

用户授权按阶段调整预算，本次为单案例缺陷验证将开发日硬上限由24改为28，其他免费保护及旧消耗保留。前文24次为前一验收阶段记录；正式任务档位仍未实现。

## 9. 模型角色与成本决策补充（2026-09-26，用户确认实施）

产品定位、渠道扩展顺序和质量门槛不变。先验证Qwen3.8-Flash思考模式承担独立复核；DeepSeek思考作为对照，Qwen3.8-Max仅作小规模能力参照与后续增强候选。没有实测收益前，不将Max设为默认，不固定串行调用三个模型。

渠道选择与模型选择分开：渠道基于任务、已接入能力及授权；模型配置基于角色和任务复杂度。平台数量增加不自动提高模型档位或复制任务预算。简单提取候选用非思考，复杂分析/修正和复核候选用思考；同模型不同上下文也可分角色，但不能声称错误独立。

实现要求：每个新任务绑定角色模型、思考开关、总输出预算和超时；思考Token进入预算和usage；追加获取仍为分析和复核预留资源。旧任务、旧配置和旧账本不追溯更改。

本阶段只实现固定角色配置和可复现对照，不增加模型驱动的自动选模器。后续升级依据应是可定位的证据冲突、经测试的困难任务类别、一次修正仍存在关键问题等；来源缺失先补查或明确未知，网络失败与格式错误单独处理，不一律换贵模型。自动升级到Max尚未实现。

新增验收要求：同题同证据比较漏检、误报、理由正确性、结构有效性、时延和实际用量；正确稿必须纳入对照；新配置不得绕过版本、引用、预算或免费保护。开启思考或切换模型本身不等于质量通过。日金额上限和普通/增强产品档位仍属后续规划。

代码与对照见[思考复核方案及结果](THINKING-REVIEW-2026-09-26.md)、[适配说明](MODEL-GATEWAY.md)、[成本核算](MODEL-SELECTION-AND-COST-2026-09-26.md)。当前已实现可选配置，网页默认仍保留历史组合，是否切换由本次真实质量验证决定。开发日上限本阶段由64调整到80，旧占用保留，不是正式产品套餐。


2026-09-27实测决定：完成14次请求后结束本阶段；179项程序测试通过。Flash思考在简单正确稿上可用，但真实题仍漏检且存在引用失真；Max本轮同样未通过，DeepSeek长资料预算/传输问题未解决。因此候选配置可调用、网页默认不切换，三者均未被本轮认证为可靠复核方案。下一项质量工作限定为原文片段编号与例外条件检查，再用新题验证；不将新平台、自动路由或默认升级Max并入该工作。详细失败与成本全部保留于上述实测报告。

### 引用与修正机制补充（2026-09-27）

模型选择原文片段编号，程序据来源版本填入原文与定位；完整证据上下文保留，片段切分不能被当作语义独立或事实正确证明。后台记录原始回答、绑定映射与哈希，页面和导出沿用统一refs结构。复核逐目标标注条件是否缺失；承认影响答案的条件遗漏却放行属于可识别矛盾。修正者必须先核对原审稿意见并给证据；反驳与实质改稿不能在同一目标上互相矛盾。

该机制已作为后台显式候选实现，网页默认尚未切换。验证固定为最多8次Flash调用，不调用Max，不重新调参求通过；详情见[片段与条件复核改进](SEGMENT-REVIEW-2026-09-27.md)。上述约束只能拦截结构矛盾，不能替代人工对实质错误和无依据推论的评测。


本补充本轮执行结论：191项程序测试通过，实际5次Flash调用后停止；新资料题完成模型复核但人工发现未充分依据来源的补充，旧例仍漏检。故引用回填候选已经实现，整个复核契约仍未验收，不启用为网页默认，不将模型pass等同人工质量通过。其余固定收尾顺序不变。

## 10. 复核输出简化及限制说明覆盖补充（2026-09-27）

开发候选compact-v2替代上一候选的重复字段要求：模型按目标给出支持与否、理由、证据编号，程序仅派生展示字段和修改请求。A回答、H假设、L限制说明全部进入复核；限制中的括号、常识补充和推论不能免检。L使用稳定顺序ID修正，不允许在修正中删除或新增限制槽位；修正后仍须独立再核查。CSV增加limitation行，与Markdown共享最终稿内容。

证据导航只能帮助定位，全文仍保留；引用绑定成功不证明引用足以支持断言。旧模式与历史记录保持兼容，不自动改写状态。任务输入上限可在开始前缩小，以匹配真实资料范围和免费余额；超限拒绝，不截断来源；预留必要复核容量和历史用量规则继续生效。

本轮6次Flash调用全部有完整用量，结构与引用有效；正确稿通过，混合题标签正确但理由仍有错误，VS Code及Bitwarden旧稿仍有关键漏检。新Zotero题核心回答有据，但不能据此认定多题质量已通过。200项程序测试与真实模型质量分别验收。候选未启用为网页默认，不将Max升级为刚需。完整结果、成本及阶段边界见[固定验证记录](COMPACT-REVIEW-2026-09-27.md)。

## 11. 网页预览版交付与质量认证分开（2026-09-27）

用户在讨论后确认继续推进并要求既有工作不倒退。本节作为当前实施约束，替代前文“必须先通过全部语义回归再接网页”的串行安排，保留v0.2允许预览交付的规则。历史失败不改判，完整跨平台首版与稳定质量认证仍未完成。

- 保留方案A、来源中心、旧版回放、历史任务、取消、暂停、恢复、关联研究、引用和导出。仅新任务默认切换到已测试的Flash分析/修正＋Flash思考复核、compact-v2与SSE；策略写入任务，旧任务恢复沿用旧策略。`--model-policy legacy`保留显式兼容入口。
- 原始`passed`状态表示模型检查结果，历史文件不重写。网页和新生成导出显示“本轮模型复核未发现问题”，重要结论仍需核对；不代表事实认证或经人工质量验收通过。
- 不增加数值置信度、自动风险评分、更多Agent或Max升级。正常流程仍为获取→分析→复核→必要时一次内容修正及再复核→交付。现有必要授权/范围处理继续保留。
- 密钥泄露、来源身份错误、失败冒充成功、预算失控、未接入渠道冒充可用、版本混用仍阻断发布。语义缺陷继续记录在质量台账，不能在演示中冒充正确结果；其存在不阻断明确披露边界的课程预览版。
- 多平台方向不变：网页预览交付后先做小红书搜索及正文读取，再根据实际需求按操作逐项接入。统一证据与流程复用，不为每个平台增加一套Agent。

本轮固定范围、验收及交付记录见[网页预览收尾单](WEB-PREVIEW-RELEASE-2026-09-27.md)。不再追加困难样例调优轮次；完成本轮网页验收后整理既有GitHub仓库更新。

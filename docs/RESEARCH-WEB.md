# 本机研究工作台

2026-09-23。入口脚本为 `research_web.py`。工作台只监听 `127.0.0.1`，默认展示四个离线回放案例；任务输入区还可以在确认计划后执行公开网页获取。离线回放使用固定虚构资料和预设响应，公开网页获取不调用模型。

## 页面流程

1. 启动：

   ```sh
   .venv/bin/python research_web.py --port 0
   ```

   终端打印一次性本机入口。入口重定向到带短时会话令牌的本机页面；Cookie可用时使用HttpOnly Cookie，内置浏览器不持久Cookie时使用页面内存令牌。所有任务API仍要求本机Host、会话、同源Origin、SameSite/Fetch校验和CSRF令牌。静态资源不含任务数据，可以匿名由同一监听器读取。

2. 选择回放：页面显示输入问题、纳入笔记数、已知作者数和同作者标记。点击“运行回放”创建幂等任务；同一个request_id重发不会创建第二个任务，同一时间只有一个任务执行。

3. 查看过程：任务记录显示处理中／已完成／已停止，详情显示回答、`answered/unknown/omitted`覆盖、假设、引用原文、版本和停止原因。刷新页面不会丢失本机记录；运行中退出后下次启动会标记中断，不自动重试。

4. 导出：结束后可以下载 Markdown 和 CSV。两者共用同一份结构化结果；CSV 对公式前缀做了文本转义，防止打开表格时被当成公式。报告和CSV都保留离线回放声明、作者计数、同作者分组和总体未知限制。

5. 预算预检：页面后台提供预检接口，但显示当前案例的预算状态。它不会读取模型密钥，也不会创建预算或发请求。已有案例预算消耗后，真实入口必须使用新的、明确批准的预算文件和 `run_research.py --execute`，不是点击回放按钮。

6. 任务输入与获取：用户可以填写问题、地区和时间范围，选择公开网页。页面先返回研究计划，逐步显示负责人和输出；点击“确认计划并获取公开网页”后才创建采集任务，后台调用 Exa 和 Agent-Reach，页面显示候选网址及逐页状态。当前只支持公开网页，勾选小红书不会被偷偷接受；这一步仍不调用模型。

7. 公开网页获取适配层：`research_acquisition.py` 已把 Exa via mcporter 的 JSON 结果解析成去重候选，再调用 `collect_page.py` 的 Agent-Reach WebChannel / Jina Reader 保存逐页证据。它使用参数数组和 `shell=False`，限制结果数为 1–5，单页重试最多两次；不会登录、读取 Cookie 或调用模型。一次电梯公开资料实跑记录见 [`runs/public-web-elevator-2026-09-23/RESULT.md`](../runs/public-web-elevator-2026-09-23/RESULT.md)。

8. 证据准备：用户在采集完成后点击“准备分析资料”，程序验证每个正文的来源编号、URL、采集时间和 SHA-256，再生成 `analysis-input.json`。页面展示 S1…来源、范围限制、分析问题和保存原文；失败来源不能进入分析，范围外或发布日期未核实的资料保持限制状态。该步骤不调用模型，且会重新校验已生成包，防止静默复用被修改的正文。

9. 角色交接预览：证据准备后可查看分析、复核、修正的调用顺序和输入/输出契约。当前试验路由显示 Qwen 分析/修正、DeepSeek 复核；复核等待分析稿哈希，修正只有在 `revise` 时创建，预览调用数始终为0。预算状态为 `new_budget_required` 时只展示阻断原因，不会联网或读取密钥。

10. 正式执行入口已做阻断验证：对已消耗预算的当前证据包重复运行不会恢复旧台账，不创建半成品输出、不自动重试、不新增 API 调用。

命令行实跑示例（会产生公开网页请求，但不会调用模型；每次使用新的输出目录）：

```sh
.venv/bin/python research_acquisition.py \
  "elevator predictive maintenance official product information" \
  --objective "优先寻找厂商官方资料，排除泛 SEO 摘要" \
  --output runs/public-web-elevator-next/sources
```

## 四个回放案例

- 引用修正后通过：第一版有省略号引文，程序先拦截，修正一版后进入预设复核。
- 复核结果无效：复核自称通过，却引用不存在的来源编号，程序拒绝通过。
- 剩余名额不足：只给两个模拟名额，程序不启动无法完成的修正。
- 达到修正上限：一次修正后仍需修改，程序停止并保留两个版本。

这些案例由`runs/offline-flow-2026-09-23/scenarios/`提供。离线回放仍使用预设案例；实时公开网页获取由单独的采集任务执行，不会被离线回放按钮触发。真实意图路由、采集证据接入分析结果页、模型分析和小红书仍未接入。

## 状态边界

`TaskStore`只开放结构化任务详情，不能通过URL读取任意本机文件、模型请求、响应或密钥。后台线程异常只显示通用“运行失败”，详细异常留在本机开发日志之外；生产接入前还需更完整的结构化错误事件。输出目录权限700，运行记录在Git忽略的`.local/web-runs/`。

工作台本轮新增9项HTTP/UI测试，网页获取适配器新增6项测试，证据准备新增2项测试；配合模型适配、流程、旧试测和连接测试，当前全套96项测试通过，另有前端脚本语法检查。预览页面已保留在当前任务的本机浏览器标签中。

下一步：按 [MVP 冻结单](MVP-v0.1-FREEZE.md) 把证据包交给结构化分析；在获得新的、明确批准的模型预算后，才执行分析、独立复核和有限修正。没有新预算时继续允许计划预览、公开网页采集和离线回放，不调用模型。

# 本机研究工作台（方案 A 实施版）

2026-09-26 更新。运行 `.venv/bin/python research_web.py --port 0` 后，启动入口默认打开方案 A 实施版（`web/workspace.html`、`workspace.js`、`workspace.css`）。旧工作台保留在同一服务的 `/legacy`，可从侧栏打开。独立交互草稿仍位于 `prototypes/`，不连接真实后台。

## 新版实际流程

1. 输入问题、地区/时间与来源，点击一次“开始研究”；后台 `research_live.py` 建立持久任务。
2. 自动执行 Exa 搜索、Agent-Reach/Jina 读取最多3个候选、证据哈希与容量校验。
3. 免费额度记录有效、配置可用时，自动创建绑定本次证据的预算，调用 Qwen 分析→DeepSeek 复核→按条件修正一次再复核。新研究最多5次模型请求，覆盖一次格式修复和一次内容修正；失败尝试也占上限。
4. 页面轮询实际后台状态，展示稿件、引用原文、复核问题、缺口和停止原因；Markdown/CSV读取同一结果。没有模型结果时保留资料与明确提示，不填模拟内容。
5. 额度记录缺失、过期或不足时进入 `waiting_user`，保留已获取证据；在运行设置核对并填写余额后，“检查后继续”仅从模型前的预算检查恢复，不重新搜索。未接入必需来源也暂停，但不能靠重试按钮伪装接入。
6. 取消后停止新派发，在途网络请求结束前仍占执行名额；已发生用量保留。刷新重读原任务，服务重启时正在执行的任务标中断，不自动重放；等待额度的任务可以重新检查后继续。
7. 修改范围或继续研究建立关联任务，不覆盖旧报告。普通关联研究会重新采集。仅引用校验失败可点一次“修正引用并复核”，创建独立记账的关联任务，核验并复用父任务证据和失败草稿；不重置原记录、不无限重试。每次草稿检查另存不可覆盖的版本文件。

8. 已有有效草稿和 `revise` 意见但预算不足时，可一次“按复核意见修正并再复核”：复用绑定版本，不重复搜索和首次复核。若这个修正任务在首次请求因连接/用量错误停止，可再创建一次“重试连接并完成修正”的关联任务；仅限未生成新稿的首次失败，不支持递归恢复。旧未知用量完整预留，新任务重新核验剩余预算、证据和草稿/复核哈希；失败后不自动循环。

## 引用定位由程序填写

模型仍负责选择来源编号、连续原文和撰写结论。结构与原文校验通过后，程序根据该来源已有的 `locator` 填回定位标签；只有正文已核对、来源存在且未排除时才处理。虚构引文、未知来源、无效结构均不能借此通过。

原模型响应和每次绑定前草稿保留，版本记录包含绑定前后哈希及逐条 `location_bindings`。只改定位标签，不改引用、来源、回答或未知状态；独立复核收到绑定后的版本，复核状态不会由定位绑定设置为通过。页面的“过程与复核”说明程序填写了几处定位。旧任务、旧预算和旧复核状态不回写。

## 免费预算与配置

当前使用**开发验收配置**，限制适用于本机网页的真实运行，不代表正式产品的固定套餐。目前不支持档位切换或按金额设置日预算；快速／标准研究与费用上限见 [PRD 后续规划](PRD-v0.3.md)。

- 密钥仍只在本机 `.local/`，前端不接收密钥或供应商原始响应。
- `research_budget.py` 记录用户在控制台核实的余额和“用完即停”状态，有效期24小时；它不是自动平台余额查询。
- 当前闭环验收阶段：新研究预留5次、引用修正4次、已有复核的修正/连接恢复2次、复核失败后重新复核3次；每模型300,000 Token容量。每日（UTC）基础12次，按提交任务需要以4次为步长自动增加至最多52次；调整上限和原因写入分配记录，不改旧任务授权、不清旧账本。已结束且用量已知时释放未用名额，在途及用量未知保留预留。请求不足以覆盖本任务阶段时不拆散派发；Token与免费额度仍单独约束。
- 额度观察刷新不清除历史台账或当日调用占用。用户已授权按开发阶段合理调整策略；当前12–52次为验收阶段配置，后续调整须保留旧账本并记录原因。已有合理调用授权由任务提交沿用，不逐次弹出批准；不自动充值或开通付费服务。
- 每任务上限10分钟，在每个新请求前检查；在途请求按各自超时收拢，停止不意味着撤销已发送请求。
- 所有真实任务、来源、预算及响应保存在忽略提交的 `.local/live-research/`、`.local/web-budget/` 与现有模型账本目录。
- 当前来源中心合并“网页搜索＋读取”为一个公开网页入口，共15个目录入口；仅公开网页可执行，其余是未接入目录，不读取登录态、不安装平台组件。

## 接口与本轮验证

受原有本机会话、Origin、CSRF及静态资源CSP规则保护：

- `GET /api/live/bootstrap`：脱敏能力及预算状态。
- `GET/POST /api/live/tasks`：历史及一次提交。
- `GET /api/live/tasks/{id}`：结果、事件、证据及来源失败记录。
- `POST /api/live/tasks/{id}/cancel`、`/resume`：取消及额度阻塞恢复。
- `POST /api/live/tasks/{id}/retry-citations`：引用失败的一次关联修正；仅接受request_id，证据及草稿必须匹配旧版本哈希。
- `POST /api/live/tasks/{id}/continue-review`、`/retry-connection`：已有复核的一次继续，以及该修正首次连接失败的一次恢复；仅接受request_id，分别校验资格、版本和预算。
- `POST /api/live/quota`：记录已核对免费额度；运行中禁止修改。
- `GET /api/live/tasks/{id}/report.md`、`/materials.csv`：带状态的导出。

当前20项集成测试及全套129项测试通过，测试中的模型传输使用替身。真实网页任务取得3份通力中国正文，Qwen分析/引文修正后由DeepSeek提出1项限制说明；追加修正首次连接失败后，保留未知用量并有界恢复，2次真实调用完成修正＋再复核，得到 `passed / review_passed`。网页引文、继承复核与新复核、Markdown／CSV均已检查。单题通过不代表整体质量；详见[本轮记录](../runs/workspace-a-2026-09-26/RESULT.md)。

## 旧版工作台（历史行为，仅 /legacy）


2026-09-23。入口脚本为 `research_web.py`。工作台只监听 `127.0.0.1`，默认展示四个离线回放案例；任务输入区还可以在确认计划后执行公开网页获取。离线回放使用固定虚构资料和预设响应，公开网页获取不调用模型。

## 页面流程

1. 启动：

   ```sh
   .venv/bin/python research_web.py --port 0
   ```

   终端打印一次性本机入口。入口重定向到带短时会话令牌的本机页面；Cookie可用时使用HttpOnly Cookie，内置浏览器不持久Cookie时使用页面内存令牌。所有任务API仍要求本机Host、会话、同源Origin、SameSite/Fetch校验和CSRF令牌。静态资源不含任务数据，可以匿名由同一监听器读取。

2. 选择回放：页面显示输入问题、纳入笔记数、已知作者数和同作者标记。点击“运行回放”创建幂等任务；同一个request_id重发不会创建第二个任务，同一时间只有一个任务执行。

3. 查看过程：任务记录显示处理中／已完成／已停止，详情显示回答、`answered/unknown/omitted`覆盖、假设、引用原文、版本和停止原因。刷新页面不会丢失本机记录；运行中退出后下次启动会标记中断，不自动重试。

4. 导出：结束后可以下载 Markdown 和 CSV。两者共用同一份结构化结果；CSV 对公式前缀做了文本转义，防止打开表格时被当成公式。报告和CSV都保留离线回放声明、作者计数、同作者分组和总体未知限制。

5. 预算预检：页面后台提供预检接口，但显示当前案例的预算状态。它不会读取模型密钥，也不会创建预算或发请求。已有案例预算消耗后，真实入口必须使用新的、明确批准的预算文件和 `run_research.py --execute`，不是点击回放按钮。

6. 任务输入与获取：用户可以填写问题、地区和时间范围，选择公开网页。页面先返回研究计划，逐步显示负责人和输出；点击“确认计划并获取公开网页”后才创建采集任务，后台调用 Exa 和 Agent-Reach，页面显示候选网址及逐页状态。当前只支持公开网页，勾选小红书不会被偷偷接受；这一步仍不调用模型。

7. 公开网页获取适配层：`research_acquisition.py` 已把 Exa via mcporter 的 JSON 结果解析成去重候选，再调用 `collect_page.py` 的 Agent-Reach WebChannel / Jina Reader 保存逐页证据。它使用参数数组和 `shell=False`，限制结果数为 1–5，单页重试最多两次；不会登录、读取 Cookie 或调用模型。一次电梯公开资料实跑记录见 [`runs/public-web-elevator-2026-09-23/RESULT.md`](../runs/public-web-elevator-2026-09-23/RESULT.md)。

8. 证据准备：用户在采集完成后点击“准备分析资料”，程序验证每个正文的来源编号、URL、采集时间和 SHA-256，再生成 `analysis-input.json`。页面展示 S1…来源、范围限制、分析问题和保存原文；失败来源不能进入分析，范围外或发布日期未核实的资料保持限制状态。该步骤不调用模型，且会重新校验已生成包，防止静默复用被修改的正文。

9. 角色交接预览：证据准备后可查看分析、复核、修正的调用顺序和输入/输出契约。当前试验路由显示 Qwen 分析/修正、DeepSeek 复核；复核等待分析稿哈希，修正只有在 `revise` 时创建，预览调用数始终为0。预算状态为 `new_budget_required` 时只展示阻断原因，不会联网或读取密钥。

10. 正式执行入口已做阻断验证：对已消耗预算的当前证据包重复运行不会恢复旧台账，不创建半成品输出、不自动重试、不新增 API 调用。

命令行实跑示例（会产生公开网页请求，但不会调用模型；每次使用新的输出目录）：

```sh
.venv/bin/python research_acquisition.py \
```

## 四个回放案例

- 引用修正后通过：第一版有省略号引文，程序先拦截，修正一版后进入预设复核。
- 复核结果无效：复核自称通过，却引用不存在的来源编号，程序拒绝通过。
- 剩余名额不足：只给两个模拟名额，程序不启动无法完成的修正。
- 达到修正上限：一次修正后仍需修改，程序停止并保留两个版本。

这些案例由`runs/offline-flow-2026-09-23/scenarios/`提供。离线回放仍使用预设案例；实时公开网页获取由单独的采集任务执行，不会被离线回放按钮触发。真实意图路由、采集证据接入分析结果页、模型分析和小红书仍未接入。

## 状态边界

`TaskStore`只开放结构化任务详情，不能通过URL读取任意本机文件、模型请求、响应或密钥。后台线程异常只显示通用“运行失败”，详细异常留在本机开发日志之外；生产接入前还需更完整的结构化错误事件。输出目录权限700，运行记录在Git忽略的`.local/web-runs/`。

工作台本轮新增9项HTTP/UI测试，网页获取适配器新增6项测试，证据准备新增2项测试；配合模型适配、流程、旧试测和连接测试，当前全套96项测试通过，另有前端脚本语法检查。预览页面已保留在当前任务的本机浏览器标签中。

下一步：按 [MVP 冻结单](MVP-v0.1-FREEZE.md) 把证据包交给结构化分析；在获得新的、明确批准的模型预算后，才执行分析、独立复核和有限修正。没有新预算时继续允许计划预览、公开网页采集和离线回放，不调用模型。

## 复核后的关联修正

当有效草稿已获 `revise`，但当前预算不足以完成修正＋再复核，且尚未执行内容修正时，可创建一次关联任务。沿用已核验的证据、草稿和复核版本哈希，直接修正再独立复核；继承的复核标为历史意见，不算新调用。旧任务不覆盖、不重新搜索。要求补来源、版本不符、已修正一次或关联任务本身均不能用此入口继续；仍受当日实际调用与Token预算约束。接口为 `POST /api/live/tasks/{id}/continue-review`。

最新实测：预算修订后，新网页已完成真实DeepSeek复核并交付有效但待修正的报告；追加修正遇接口响应／用量错误，保留历史复核和预留。功能路径已执行，通过终稿仍未取得，详见运行记录末节。


## 逐项覆盖与连接诊断（2026-09-26 缺陷验证阶段）

新证据包v0.2将明确问句、分号、换行和逗号后的疑问从句拆为检查项，保留完整任务上下文；最多8项原始检查，超出部分合并而不丢弃，另加日期/地区/适用条件未知检查。它不是完整语义规划，复合短语和隐含需求仍需人工检查。页面可展开核查清单，覆盖计数只表示这些检查项；每项回答都进入既有引用校验与独立复核。v0.1历史包沿用原生成规则，不修改原哈希与旧稿。

网络诊断仅使用固定类别（超时、DNS、TLS、远端断连等）和请求/读取/解码阶段，不存异常原文。页面过程区读取脱敏分类；没有新诊断的历史失败不能倒推根因。未知用量与不自动重发规则保留。

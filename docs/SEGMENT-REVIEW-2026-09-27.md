# 引用片段与条件复核改进

本阶段只完成公开网页首版收尾清单的第1项：改进引用和复核机制。暂不改变网页默认模型、不调用Max、不增加新平台。实现不等于质量通过。

## 这次改变什么

- 原文按顺序完整划分为片段，每段绑定来源内容哈希与字符偏移；模型输入保留所有片段，不按草稿过滤，不静默裁掉上下文。长表格可能跨段，必须结合相邻表头理解。
- 模型只返回实际片段编号。程序填写原文、来源与定位，保存原响应、绑定结果、目录哈希和映射记录。旧稿/旧结果仍保持原契约。
- 独立复核每个目标显式给出条件核查：未发现相关例外、条件已覆盖、遗漏改变答案的条件、证据不足。声明条件遗漏却放行，或缺少该条件依据，程序拒绝。
- 修正角色先给出对复核意见的接受/反驳判断及原文依据。反驳意见时不能悄悄修改同一目标；仍要经过独立再复核。程序只能检查结构和证据身份，不能保证模型理解正确。
- 新契约通过`run(..., reference_mode='segments-v1')`显式启用；模型配置与引用契约分别记录。网页默认保持旧模式，待验收后再接入。

## 实测前固定的验证范围

只使用`qwen-review-thinking-json-v2`：分析/修正为Flash非思考，复核Flash思考4096、总输出8192，JSON Object、SSE。模型参数不再按结果调优。

1. 现有虚构混合错误题：1次复核，8组目标，检查漏检与误报。
2. 现有虚构正确稿：1次复核，2组目标，检查是否无依据要求改写。
3. 保存的VS Code旧稿：1次复核，关注语言特定条件遗漏和优先级误读。与旧配置仅作探索性比较，不是盲测或统计结论。
4. 新资料题：Bitwarden个人保险库导出功能，以[官方导出说明](https://bitwarden.com/help/export-your-data/)为指定来源，通过Agent-Reach实际读取。询问附件/垃圾箱/Send的导出范围，以及两种加密导出的跨账户与密钥轮换限制。分析→复核→必要时一次内容修正→再复核，最多5次请求（含允许的格式修正），不用模型执行任何真实密码导出。

合计最多8次模型请求；请求或引用契约失败不额外重跑，同题不改提示词再求通过。新资料题不参与代码/提示词调优；同题所有阶段共享已冻结证据，人工按该原文判读。指定链接读取不冒充网页自动搜索或UI端到端验收。

质量通过条件：格式和引用有效；混合题无关键漏检、正确稿无实质误报；旧题指出改变答案的例外而非只给revise；新题结论及必要条件经人工核对，修正不引入新错误。程序测试通过不能替代这些条件。

### 下一步收敛

引用准确复制的问题已有可运行解决办法，但“选择的证据是否足够”和“是否误读条件”仍是语义问题。当前不推荐直接启用整个新契约；下一步仍属于固定收尾清单第1项的质量工作：减少重复填写引用造成的无效输出，针对关键条件做更聚焦的证据核查，同时让限制说明中的实质断言进入检查范围。不能靠继续添加必填字段或把同一题反复跑到pass来验收。完成后才进入默认配置选择及网页整体验收；未新增平台或功能范围。

## 当前可选配置

引用机制另有显式候选`reference_mode='segments-v1'`，与模型配置分开：`research_flow.run`将完整来源按顺序展示为片段；网关先无损重建原case并核对批准哈希，不能只相信输入自报的哈希。回答、复核、修正及再复核中的编号由程序回填为原有refs结构；保留原响应、绑定前后哈希与片段偏移。新契约的条件核查/修正依据失败会明确停止，不自动迁就输出或更换模型。旧literal模式与旧任务保持原行为；网页尚未启用候选。实现及实测见[片段复核阶段](SEGMENT-REVIEW-2026-09-27.md)。

`legacy`保持Qwen Flash分析/修正＋DeepSeek Flash复核，非思考4096输出、90秒。
`qwen-review-thinking-v1`、`deepseek-review-thinking-v1`、`max-review-thinking-v1`分别只改变复核配置；`qwen-thinking-v1`提供全部三个角色使用Qwen Flash思考的候选配置。通过`WebBudget.issue(..., model_profile=...)`选择，先核对所需模型的免费额度；不是运行中随意换模型。

新grant的`role_options`对analysis/review/repair分别固定`enable_thinking`、`max_completion_tokens`、`timeout_seconds`。思考候选默认总输出8192、180秒；Qwen发送thinking_budget=4096，DeepSeek发送reasoning_effort=low，不混用两家的参数。v1只在非思考Qwen请求启用JSON对象模式；思考请求仍要求JSON并执行相同本地校验。v2的显式JSON配置见下文。

适配补充：首轮v1不变，新增`qwen-review-thinking-json-v2`与`max-review-thinking-json-v2`，根据官方Qwen3.8支持范围在思考请求同时发送JSON Object参数，独立记账验证。它只约束格式，不替代引用和语义检查；不是把旧无效输出自动修成通过。

`deepseek-review-thinking-budget-v2`只将复核总输出提高到16384、超时240秒，用于区分预算截断和语义失败。候选配置发放门槛为每个所需模型至少20万可用Token（足以覆盖一次最大输入＋最大总输出）；每模型上限取30万和可用余额的较小值，调用前仍按实际消息及后续复核合并预留，余额不足则拒绝。历史网页默认配置继续原30万发放门槛，不更新旧grant。

使用`max_completion_tokens`限制思考＋回答总输出，并按官方最多10 Token偏差预留。程序按当前配置计算分析及后续复核容量，同模型角色的容量累加。供应商返回usage（含思考）照实记账；截断、超限、断连保持失败，不自动重试或切换模型。新增Max必须同时存在于本机凭据模型范围和有效免费额度观察中，列入支持目录本身不授予调用权限。

旧grant无role_options时继续发送max_tokens=4096，哈希、历史数据和既有角色不变。配置哈希固定后禁止中途修改。原始响应仅在本机忽略目录，页面交付回答不展示模型思考内容。

接口依据：[百炼Chat参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)、[DeepSeek参数](https://help.aliyun.com/zh/model-studio/deepseek-api)。以下记录按各历史阶段保留。

## 输入、职责与输出

| 部件 | 输入 | 负责什么 | 输出 |
| --- | --- | --- | --- |
| 调度器 | 证据、任务、上一版草稿／复核 | 选择analysis、review或repair；最多一次修正 | 本次独立请求的两条messages |
| 模型适配器 | 阶段＋messages＋批准预算 | 选择角色模型、校验范围和额度、读取本机凭据、调用API | 回答文本、调用台账、usage或明确失败 |
| 程序校验 | 回答＋证据 | JSON、引用、覆盖、复核目标与通过条件 | 继续、修正或停止 |
| 结果输出 | 稿件、版本、状态与计量 | 分清真实调用与回放、未知用量与已知用量 | result.json、report.md和本机过程记录 |

候选角色：分析和修正用`qwen3.8-flash`，复核用`deepseek-v4.1-flash`。角色映射属于预算配置，可以替换为已核实可用的候选模型；不是散落在提示词里的固定模型名。

调用沿用此前实测过的百炼北京HTTP传输，关闭思考、关闭流式、最多4096输出Token，不自动重试。Qwen开启已测过的JSON对象模式；DeepSeek该模式尚未验证，暂不发送这个参数，结果仍必须通过本地JSON与结构检查。

## 预算怎么生效

首轮12次真实调用已用完。首版电梯案例先使用一个最多4次的免费预算完成3次真实调用，随后又使用独立的最多2次免费预算完成“修正→再复核”。补充官方资料的新关联任务又使用最多4次预算完成2次初始调用；引用格式本地规范化后，以新的最多3次续行预算完成复核、修正和再复核。该任务最终仍为`revise`，所有相关台账都已消耗，不能继续重放。新入口不会读旧额度当作新额度，也不会自动创建批准文件；重复运行已用台账会停止在`budget_already_used`，在读取密钥和发送请求之前停止。

后续新的真实任务需有明确批准的本机预算文件`.local/research-budget.json`。关键字段包括：

| 字段 | 用途 |
| --- | --- |
| grant_id、authorization_note | 本次批准编号和决定记录；同编号不能改上限后重用 |
| parent_run | 关联前次任务，保留历史；不抹掉先前消耗 |
| case_sha256 | 绑定问题、日期、资料和采样规则；换范围需新任务 |
| approved、expires_at | 明确批准与有效期限；未批准或过期不执行 |
| max_calls | 本次最多2–4次请求；失败同样占用 |
| roles、token_limits | 每个角色使用哪个模型、各模型容量上限 |
| free_only=true、paid_calls_authorized=false | 仅免费额度，当前不支持付费执行 |
| free_quota_observation | 各模型剩余额度、用完即停状态和观察时间 |

当前实现要求额度观察不超过24小时且早于当前时间，这是本项目的初始保守规则，不是供应商标准。账户其他操作仍可能消耗额度，所以该观察不能代替平台用完即停或实时账单。

每次调用先检查：

1. 任务和预算范围匹配、预算未过期、没有上次失败或在途未知请求。
2. 分析／修正至少剩2个名额（它自身＋后续复核）。
3. 当前模型容量足够；如果还需复核，按复核模型单独预留容量。两种角色使用同一模型时合并占用。
4. 通过后才读取本机凭据，继续校验百炼北京HTTPS白名单、免费保护确认和模型范围。
5. 发送前持久写入started；成功／失败后写入finished。超时可能已经消耗额度，usage未知不能记成0。

Token预留采用**UTF-8字节数＋协议余量＋输出上限**，不是精确tokenizer。复核先按最大允许输入180,000字节，加输出4,096及余量1,024，预留185,120的容量；因此可能拒绝实际很便宜的任务，但避免先做完分析才发现复核没额度。返回后按供应商有效usage结算。若实际计量超过预估，记录实际用量并停止后续调用；不能承诺客户端估算实现绝对封顶。

当前不计算人民币原价或承诺实际扣费为0：付费未授权，实际账单状态为未核实。后续若支持付费，必须先增加版本化价格、金额上限和明确授权，不能沿用免费配置直接付费。

## 持久化与失败

- 台账按批准编号放在`.local/research-budgets/`，不跟随结果输出目录重置。
- 使用文件锁防止同预算并发；崩溃后的未完成started保留。新进程见已消费批准即停止，本版不提供恢复或手动复核重试。
- 预算中途被修改会停止；不能给同一编号扩容后掩盖历史消耗。
- 无usage、HTTP异常、截断、空回答和密钥回显均停止；不自动改模型或重试。
- 格式无效但usage完整时，计量照记；后续由调度器标记结果不可用，不能把“HTTP成功”当成“复核通过”。
- 保存本机请求和脱敏响应，使用目录权限保护；不输出密钥、供应商异常原文或思考内容到终端。原始响应不默认公开。

本版尚未实现跨任务链的自动合计和平台账单同步。关联信息与旧账本保留，但不声称这是全账户费用上限。

## 运行方式

只预检（当前可运行，不读密钥、不发请求）：

```sh
.venv/bin/python run_research.py \
  --case runs/model-trial-inputs-v1/app-feedback.json \
  --date 2026-09-23
```

此命令显示任务哈希与预算配置状态。它不代表账户连通性或剩余额度验证。`--execute`才进入真实执行，并且必须先有批准预算；真实输出限制在`.local/`的新目录，不能覆盖历史。已消耗的案例预算不会因更换输出目录而重放。

重放API适配器集成演示（临时假凭据＋模拟HTTP响应，不联网；输出目录必须不存在）：

```sh
.venv/bin/python demo_model_gateway.py --output runs/my-gateway-demo
```

测试中的批准记录均明确标记MOCK，存于临时目录并随测试清理；不是给生产创建新额度。每个模拟响应的100输入＋50输出Token也是固定测试值，不是估算或实际消耗。

## 可选流式传输（开发验证）

预算可显式声明 `transport_mode: sse`，省略时仍为 `json`。SSE请求携带 `stream_options.include_usage=true`；仅在收到结束原因、有效用量和`[DONE]`后输出重建响应。中途EOF、格式错误、超限、工具调用均停止，不自动重发；诊断只记录阶段、事件数和字节数等元信息。时限是socket读取超时加事件间经过时间检查，不承诺严格的总墙钟上限。首个事件时间从响应头到达后开始计，不是完整请求首Token延迟。一次DeepSeek真实验证成功，不能外推Qwen或长期稳定性。参考[官方流式说明](https://help.aliyun.com/zh/model-studio/stream)。

## 可选任务输入容量与复核契约（2026-09-27）

预算可选`max_input_bytes`，范围8192–180000，缺省沿用180000。输入容量随预算哈希固定，运行中不可更改；超过实际字节上限拒绝请求，不静默缩减来源。分析/修正之前为复核预留该输入上限及完整输出容量，同模型角色仍合并预留。WebBudget接受此参数后可以为较小任务分配较小容量；免费余额、历史占用、失败未知用量和日上限不会重置，也不是新增免费额度。

`run(..., reference_mode='compact-v2')`显式启用简化复核，模型配置独立指定。模型只输出判断与片段编号；程序严格绑定原文并派生重复字段。回答、假设、限制说明均覆盖，补丁回执和独立再复核保持。生产网页默认不自动切换。6次真实请求的本轮结果与尚存语义漏检见[阶段记录](COMPACT-REVIEW-2026-09-27.md)，不能将有效JSON或正确片段编号等同事实正确。

# 两款候选模型首轮试测方案

日期：2026-09-23。状态：首轮真实试测已收尾，12次总上限已用完；已知72,285 Token，另有1次失败精确用量未知。未授权付费，尚无已通过质量验收的终稿。最新结果见 [收尾报告](../runs/model-trial-2026-09-23/FINAL.md)。

## 目的与范围

首轮比较 Qwen3.8-Flash 与 DeepSeek-V4.1-Flash，验证模型能否根据同一份资料完成分析和独立复核。用户于2026-09-23明确用 DeepSeek 替代 GLM；本轮不调用 GLM。Qwen3.8-Max 保留质量对照，不在此次默认调用范围。

先固定证据，避免把检索结果变化误当成模型差异。本轮不衡量意图路由、工具调用能力、真实小红书获取、完整产品效果，也不替代 PRD 的 12 题试测及后续留出集验证。

两款均通过阿里云百炼中国站、北京地域的阿里直供渠道试测。单一渠道减少首轮账户配置工作，但不保证两款服务的参数或权限完全一致。

- DeepSeek ID：`deepseek-v4.1-flash`，已由用户控制台截图与官方文档核对；不是 DeepSeek 原厂接口的 `deepseek-flash`，也不是 `vanchin/` 渠道。
- 北京接口基址：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，WorkspaceId 由实际业务空间确定。
- 用户截图显示两款各有100万免费Token，均于2026-12-23到期；截图时用完即停均关闭。这是历史快照，不是当前余额。
- 两款用完即停均开启并生效后才进行免费测试。密钥通过 `配置模型.command` 或 `.venv/bin/python configure_model.py` 在本机终端隐藏输入，保存至 `.local/model_credentials.json`，目录700、文件600且Git忽略；不在聊天、浏览器前端或 GitHub 保存。该文件是明文凭据，不应随目录分享。
- Safari 权限障碍已排除，实际观察到两款用完即停开启；本机真实凭据已经保存、API连接已经通过，无需重新配置。平台保护状态的观察不是实时账户余额或逐笔账单核验。
- 本机运行仍会把题目、选取的公开证据和草稿发送给供应商。本轮仅含公开网页历史快照和明确标注的虚构数据。

官方依据：[百炼 DeepSeek 接口](https://help.aliyun.com/zh/model-studio/deepseek-api)、[百炼兼容 Chat 接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。实际请求已接受 enable_thinking=false 并返回 usage。Qwen JSON模式完成一次修复试测：语法合法但来源字段不合约；DeepSeek JSON模式和严格Schema模式未验证。

## 测试输入与职责

| 题目 | 输入 | 模型负责的输出 | 人工核验重点 |
| --- | --- | --- | --- |
| web-facts | 已保存并通过哈希检查的3份通力中国网页；真实历史资料 | 功能、适用条件、未知和引用 | 一般多品牌维保不等于云管家全型号兼容；厂商描述不等于效果实测 |
| app-feedback | App A 的官方说明及6条模拟笔记候选；全部虚构 | 事实、样本观点、改进假设、下一步验证 | 4条纳入笔记来自3名作者；两条入口问题来自同一作者；保留相反体验 |
| review-trap | 同一组虚构证据＋人工植入错误的报告 | 问题清单、判断依据和修正动作 | 能否发现已知错误，同时保留正确的“支持5公里计划”结论 |

离线准备程序负责验证历史证据完整性、移除样例中的答案和复核状态、生成固定消息、记录 SHA-256。它不调用 API、不读取密钥，也不把准备成功算成评测通过。

```sh
.venv/bin/python prepare_model_trial.py --output runs/model-trial-inputs-v1
```

既有输出目录会拒绝覆盖。程序可从任意工作目录使用绝对脚本路径运行。生成文件由 `model_trial.py` 读取并验证哈希；准备程序自身不调用模型。

## 原定免费试测安排与上限

首轮总调用上限12次，本轮已用完，包含失败；仅使用免费额度。此前5元预算仅是建议，从未获授权，现不作为执行额度。免费额度到期、耗尽或保护状态不明时停止；不自动切换付费或其他模型。

1. 每个模型用 web-facts、app-feedback 各生成一次草稿：共4次。
2. 每份草稿交给同模型的新上下文独立复核，输入只含任务、证据和草稿，不带分析推理：共4次。
3. 每个模型复核同一份 review-trap：共2次。
4. 剩余2次留作连通性或格式修复；全部请求消耗计入台账，不额外静默重试。实际已用2次连接测试；失败后没有执行DeepSeek官网复核，最后一个调用名额用于Qwen App复核格式修复。合计仍为12次，并非完整完成原计划所有格子。

开始第一份分析前，须保留该任务独立复核所需的调用、token和金额预算。其余预算不够时不再启动新题，记录未执行。首轮不自动改稿，以便观察原始错误和复核发现能力；修正后错误减少程度需在后续有限循环试测中另测。

执行器已实现预算台账、最大输出限制和预估预留。供应商实际计费以账单为准，不能承诺仅靠客户端估计实现账户级绝对封顶；思考token计费口径和输出上限关系须先核实。超时或缺失usage视为可能已发生费用，停止新付费调用并核账，不能按零元处理。

## 公平性与记录

- 同题使用完全相同的证据和提示词；保留输入哈希，记录请求模型ID、响应模型ID（如返回）、日期、参数、提示词版本。
- 使用双方支持的结构化方式；若模式不同，明确记录，不能声称参数完全等效。优先匹配思考模式与输出限额，不支持则记录差异。
- 每次记录角色、起止时间、耗时、成功或失败、finish_reason、完整usage、免费额度消耗和估算原价（若可核实，不能当成实际扣费）。输出被截断不算完整回答。
- 缓存命中与思考token单列；避免把缓存差异当成模型本身的速度或费用优势。
- 首轮每题只跑一次，能发现明显失败，不能据此给出稳定性或综合准确率排名。必要时扩充题目并交换执行顺序。
- 正式评测应先隐藏供应商标签再评分。本轮由当前助手对照证据审阅，未做盲评、未规范计时，也没有人工搜索基线，不能声称节省百分之多少时间。
- 程序检查 JSON、字段、引用ID和原文匹配；人工负责语义支持、范围、遗漏及假设是否可执行。模型复核不能作为自己的金标准。

## 人工判分表（不得作为模型输入）

每个问题只归入 answered、unknown、omitted 之一，分母固定为任务问题数；分别展示三者数量。问题虽被回答但回答错误，另计事实错误，不因归为 answered 就算通过。

| 维度 | 记录规则 |
| --- | --- |
| 关键事实错误 | 逐条标出：编造来源或原文、无据全称断言、事实与观点混淆、样本转总体、重复作者算不同人；任一未解决不得标为可用终稿 |
| 覆盖 | answered / unknown / omitted 三栏；未知还须人工判断是否合理，避免模型把可答问题全写未知 |
| 引用支持 | 每个主要结论能否在所指原文中找到直接或有清楚限制的支持；仅引用ID存在不够 |
| 可用性 | 用户能否据此执行下一步验证，需修改哪些文字及人工核验耗时；本轮先记录，不编造数字门槛 |
| 复核效果 | 草稿已知错误数、正确发现数、漏检数、误报数；没有错误时不计算“检出率100%” |
| 成本与耗时 | 分析、复核、失败/修复分开记录；复核增加成本和耗时与发现错误一起看 |
| 最终结论 | 可进入下一轮 / 需修复再测 / 暂不采用；未调用与不通过分别记录 |

review-trap 至少有5项明确问题：不能调整训练日、两个不同用户、总体50%、全地区全版本适用、已证实减少30%流失；“立即优先开发”还缺乏优先级依据。应保留正确的5公里计划描述，避免把整份报告全部误判。输入不提示错误数量或位置。

通力题应保留兼容性未知，但实际功能必须覆盖预测性描述；App题应区分用户误解与功能缺失，明确版本未知，排除重复笔记及未知日期样本的窗口计数。

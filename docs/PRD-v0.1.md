## 2. 背景、问题与机会

### 2.1 用户目前完成研究工作的方式

用户在搜索引擎、官网和社区分别检索，打开多个链接，复制内容，再让模型总结。通常需要自行区分不同平台的访问条件，反复说明任务背景，并逐项核对结论来源。

这些工作包含五个可改善的步骤：

1. 判断去哪找：官方说明、媒体报道与个人体验适合回答不同问题。
2. 取得可用正文：有的工具只返回摘要，有的平台需要登录，有的页面是验证页。
3. 对齐口径：日期、地区、规格、实体或统计单位不一致时不能直接合并。
4. 判断总结是否有依据：链接存在不代表支持该句结论，评论转述不等于事实核验。
5. 保留过程：用户希望知道哪些没找到、哪里改过、结论何时形成，而不是只有最终文字。

以上是基于项目讨论的需求假设，尚无用户访谈或市场规模数据。需要在首版试用中验证是否显著减少核对和整理时间。

### 2.2 产品价值主张

把“理解任务—选择来源—获取证据—整合—复核—交付”组织成可重复执行、可追溯、可控制范围的流程。用户用自然语言提出需求，系统在实际具备能力和授权的渠道内执行，明确展示证据与缺口。

### 2.3 与通用 Agent 的关系

通用 Agent 也可能完成这些任务。本产品拟提供的差异在于稳定的任务结构、受约束的工具选择、统一证据记录、可见的复核与停止规则，以及交付格式。是否更准确、更省时、更便宜，必须在相同问题和来源条件下比较。

不将“使用 Agent-Reach”“有两个模型角色”“有循环”单独作为已验证的竞争优势。

## 3. 用户与使用情境

### 3.1 主要用户画像（用户已确认）

**产品经理／个人研究者**：能描述研究目标，但不想逐个平台配置工具、复制资料、整理引用；需要将结果用于产品决策准备、课程作业、行业调研或汇报。通常愿意检查证据，不需要系统代替自己做最终决策。

次要用户：中小企业的产品、售前、采购和销售人员。其招标、政策、材料价格或供应商任务需要专门字段及数据源验证，首版不以“专业数据库全覆盖”承诺交付。

### 3.3 用户故事

- US01：作为研究者，我只描述问题，系统就能提出合理的来源计划，不要求我选择具体命令。
- US02：作为产品经理，我需要区分厂商功能宣传与用户反馈，避免把两者混为已验证事实。
- US03：作为资料整理者，我能点击结论查看支持片段，而不是重新浏览所有网页。
- US04：作为使用者，我需要知道哪些平台没有访问成功，以及这会影响哪些结论。
- US05：作为课程作品作者，我能展示一次真实的“复核发现缺口→补查→修正”过程，并解释各组件职责。
- US06：作为 GitHub 使用者，我能自己配置模型密钥、运行本机网页，也能在不配置密钥时查看明确标识的样例回放。

## 4. 产品目标与非目标

### 4.1 首版目标

1. 在网页中输入研究任务，无需当前 Codex 主助手手工编排即可跑完整链。
2. 工具只在已接入、可调用和授权范围内被执行。
3. 重要事实结论可追溯到原文位置；事实、观点、推断和未知分开。
4. 每份对外标记为“已复核”的结果均经过独立模型调用及程序检查。
5. 能根据复核问题执行至少一次真实补查或改写，且按上限停止。
6. 获取失败、模型失败、预算达到、登录缺失都产生明确状态，不伪装成成功。
7. 用户可查看历史任务、导出结果，并能删除本地任务数据。

### 4.2 非目标

- 首版接通 Agent-Reach 列出的全部平台、任意账号或全站数据。
- 自动登录、自动解决验证码、自动导出浏览器全部 Cookie。
- 发帖、评论、点赞、发消息、提交表单、申请补贴、自动投标或购买数据。
- 多人协作、云端账号体系、公网 SaaS、移动端独立 App、定时监测。
- 保证信息全量、实时、客观正确，或保证复核使准确率达到某个百分比。
- 将用户评论代表性扩大为总体市场统计，或将网页摘要当成完整原文。
- 首版处理任意 PDF/OCR、视频音频、多模态采集；可访问 HTML 正文优先。
- 一开始建设复杂插件商店、多供应商动态竞价、长期记忆或企业知识库。

## 5. 成功标准与证据口径

### 5.1 产品验收硬条件

| 编号 | 条件 | 验证方式 |
| --- | --- | --- |
| G01 | 本机网页能完成至少一个网页研究任务 | 实际 API 调用及完整任务日志，不接受仅回放 |
| G02 | 第一轮分析与复核由独立调用完成 | 检查调用 ID、输入结构与证据版本 |
| G03 | 真实补查任务能够追加原文并再次复核 | 留存前后证据集、复核意见和修正版 |
| G04 | 失败来源不能被当作有效证据引用 | 故障注入及真实失败案例 |
| G05 | 执行次数、时间和输出长度限制生效 | 可复现边界测试；费用约束另见第 15 节 |
| G06 | 未安装/未登录/未实测的渠道不会显示已可用 | 能力页、计划及运行记录交叉核对 |
| G07 | 最终结果显著展示来源缺口及复核状态 | 页面和导出一致性检查 |
| G08 | 无密钥能查看回放，但不能冒充实时运行 | 两种状态的界面测试 |

### 5.2 质量指标（计划测量，不是当前成绩）

- 结论证据支持率：人工标注为受到证据支持的重要事实结论数／被检查的重要事实结论数。
- 引用可定位率：能定位到实际取得片段的引用数／引用总数。此项不等于内容真实率。
- 任务覆盖率：已回答或明确解释无法回答的必需子问题数／任务必需子问题数；“明确未知”必须单独统计，不能当作已解决。
- 复核发现率：已标注错误中被复核检出的数量／错误总量。
- 复核误报率：正确结论中被错误要求修改的数量／已标注正确结论数。
- 严重错误残留：最终仍存在的无依据全称断言、错误日期、错误地区、来源错配数量。
- 执行指标：端到端耗时、获取成功率、重复来源数、补查次数、模型调用次数、实际 token、可获得的费用估算。
- 用户指标：完成同一研究任务的人工核对时间、结果是否有用的简短反馈。

首版不使用无法解释的“综合准确率 90%”。程序测试通过数与研究回答质量分开呈现。

## 7. 端到端用户流程

### 7.1 首次使用

1. 用户在本机启动应用并打开浏览器，首页展示“实时模式未配置”或可运行状态。
2. 用户进入设置，在本机配置供应商、模型和密钥；密钥保留在服务端本地，不写进前端构建或聊天记录。
3. 点击“测试模型连接”。按钮说明可能产生一次小额调用；不在后台静默发送研究资料测试。
4. 能力页检查网页搜索与读取。检测到命令存在只能显示“已安装”，实际返回有效内容才标为最近验证通过。
5. 需要小红书时，展示具体后端准备步骤。登录/授权由用户在本机完成，不要求在聊天或导出文件中提供凭据。
6. 未完成配置也可以查看示例回放，页面持续标识“历史样例，非实时执行”。

### 7.2 正常任务

用户输入问题 → 系统解析目标与范围 → 检查澄清需求和可用渠道 → 形成计划 → 获取与去重 → 组织证据 → 生成初稿 → 独立复核 → 通过后交付。

按已确认 Q03，计划默认直接执行。默认直接执行不包括自动付费开通、注册新服务、授权新账号或安装系统级工具。

### 7.3 缺证据时

复核指出缺口 → 主助手判断动作 → 若可在已有预算和能力内补查，则检索/重读 → 新证据和新报告版本绑定 → 再次复核。

若来源已合理补查但无直接证据：明确“本次来源中未确认”，解释检索范围和未解决问题，可以形成带限制的完成结果。若某项已有结论被证据否定且未修复，不得以“有些不确定”掩盖后标记复核通过。

### 7.4 部分来源失败

- 用户未指定平台为必要来源：能继续时展示缺失平台，基于剩余证据回答，结果标为部分完成。
- 用户明确要求“小红书用户反馈”：小红书不可访问时不能以普通网页报道冒充，进入等待用户处理或结束为无法完成该部分。
- 用户指定仅使用一组链接：其中链接失败时只基于成功链接回答并说明；新增来源需要用户允许改变范围。

### 7.5 用户取消或关闭

用户点击取消后，不再调度新工具/模型请求；对支持中断的进行中请求尝试取消，否则等待超时并忽略其内容入库。已发生的 API 计费可能不能撤销，保留已消耗用量。

仅关闭页面不等于取消，后台仍在运行时任务继续；重新打开可看到状态。后台退出后任务记为中断，首版默认由用户复制任务重新执行，不静默重放可能产生费用的请求。

## 8. 意图解析与澄清需求

### FR-01 自然语言任务输入（P0）

输入内容：问题正文必填；地区、时间范围、来源偏好、指定链接、结果形式选填。首版建议问题最多 4,000 个字符，指定公开 URL 最多 5 个；超出时解释并让用户拆分，不无提示截断。

提交时生成唯一 task_id，保存原始输入。用户输入和模型归纳后的意图分别保存，不能覆盖用户原话。

验收：空问题不可提交；相同文本的两次手动提交产生不同任务；双击或网络重发同一个提交标识只生成一个任务。

### FR-02 结构化意图（P0）

| 字段 | 说明 | 缺省处理 |
| --- | --- | --- |
| task_type | research / feedback / organize_links / mixed | 不确定时允许澄清 |
| objective | 用户要解决的具体问题 | 不可擅自替换为另一主题 |
| entities | 公司、产品、品牌、服务、地点等 | 同名影响结果时询问 |
| subquestions | 拆解后的关键子问题 | 建议最多 5 个，过大则询问收窄 |
| region | 地理/市场范围 | 未指定则“未限定”，不自动认定中国 |
| time_range | 起止日期及所指日期类型 | “近三个月”保存计算后的具体范围及任务时区 |
| source_constraints | 指定、排除、仅限来源 | 明确要求优先于模型偏好 |
| output_mode | answer / materials | 无明确要求默认回答，允许切换 |
| evidence_needs | 每个子问题需要哪类来源 | 用于工具计划和最终覆盖检查 |

### FR-03 澄清策略（P0）

必须询问：关键实体无法区分；用户请求与现有来源/权限相冲突；时间或地域歧义会改变结论；用户要求超出已配置预算；任务过宽到无法形成有意义的首版范围。

可按明示假设继续：输出长度、非关键排版、未限定平台但存在明确合适来源。界面展示假设，用户可调整。

问题集中提出，建议一次不超过 3 个；每项给建议和选项。用户未回答必需澄清时保持等待；不得把超时当作同意。

例：“整理最近用户评价”若未指定产品，应询问产品；若产品明确但用户没选输出格式，可默认生成主题分类报告。

## 9. 获取计划与执行控制

### FR-04 可解释计划（P0）

每个计划步骤包含：目的、平台类别、具体操作、查询词或 URL、选择理由、所需授权、结果上限、关联子问题。用户界面显示业务语言，例如“读取官方功能说明”，技术命令放诊断详情。

计划必须先经程序校验：工具在允许列表中、参数满足结构、预算足够、平台符合用户范围、操作为只读。模型生成的任意 shell、路径或未知工具不得执行。

### FR-05 范围修改（P0）

未执行的步骤可调整；已经执行的操作不能假装撤销。若修改主题、地域或必要来源使研究对象明显改变，创建关联的新任务；单次追加澄清在当前任务保留事件与意图版本。

原任务中的来源可以被新任务明确复用，但必须标注采集时间和“历史证据”，不能修改为本次新采集。

### FR-06 预算与暂停（P0）

在计划和每个调用之前检查上限。平台登录或新增付费来源必须暂停。达到来源上限或全局时间上限则停止新调用，进入可交付性判断：有足够且已复核内容则部分完成；没有则明确停止。

不把“凑够固定平台数”作为计划目标。纯官方功能问题可能只需要官网；用户体验问题才需要社区反馈。

## 10. 工具路由与能力管理

### 10.1 Agent-Reach 的角色

Agent-Reach 是首版实际使用的接入能力组件之一。应用依据其已核实的指引和配置调用底层工具，不假设存在一个能统一读取所有平台的 Agent-Reach API。独立应用需自行实现任务调度、结构化适配、分析和复核。

记录 Agent-Reach 提交/版本、底层工具版本、后端名称和调用结果。更换获取组件时，上层继续消费统一证据；适配变更仍需回归测试，不承诺零改动。

### FR-07 能力注册表（P0）

| 字段 | 用途 |
| --- | --- |
| capability_id / adapter_id | 平台能力和本地适配器标识 |
| platform / operations | 平台及 search/read/detail/comments 等允许操作 |
| supported_content | 能处理正文、帖子、评论或仅摘要 |
| auth_requirement | 无登录、本机会话、用户 API 凭据等 |
| configuration_state | 未配置、已配置、需要登录、禁用 |
| health_state / checked_at | 未验证、最近可用、降级、失败及时间 |
| health_evidence | 是安装检查、配置检查还是实际内容探测 |
| limits | 超时、结果上限、重试策略、并发限制 |
| cost_policy | 已知价格/未知、是否已启用付费调用 |
| input_schema / output_schema | 结构校验与适配契约 |
| replacement_order | 仅允许已配置且符合权限的备用后端 |

“已配置”与“可用”分开。能力状态具有时间范围，实际调用失败会立即更新；历史一次成功不是永久可用承诺。

### FR-08 路由决策（P0）

按顺序执行：

1. 尊重用户指定或排除的来源。
2. 匹配问题需要的证据类型。
3. 在已注册适配器中筛选支持操作和参数的工具。
4. 排除未授权、不可用和预算不允许的选项。
5. 优先来源适合性，其次考虑最近健康状态、延迟、成本和覆盖范围。
6. 若选备用后端，记录原因；不得为替代某平台自动获取另一账号授权。

示例：问软件功能优先官网；问公开仓库代码而 GitHub 适配器未接入时，最多使用可读取公开页面并注明限制，不能声称完成代码级分析；问小红书评论而后端只有笔记读取时，明确评论不在本次证据中。

### FR-09 网页渠道（P0，已有部分基础）

搜索返回候选结果，正文获取是另一操作。保存标题、URL、摘要及相关性，但摘要默认仅用于定位，不作为原文完整性的证明。选择正文时优先与子问题直接相关的来源。

读取后检测空内容、错误页和明显登录页；成功仍需证据检查。支持用户直接输入公开 URL。内网地址、file URL、携带账号密码的 URL 和工具任意本地文件访问不在获取范围。

### FR-10 小红书渠道（P0 的第二交付里程碑，已确认）

最小能力：关键词搜索、指定笔记读取、保存平台 ID、内容及可获得的日期。评论是单独能力，只有经实际后端测试后才开放；不能把笔记正文当评论。

登录由用户在自己控制的本机环境完成。应用只展示连接状态和必要操作说明，不在任务日志中存 Cookie、密码或验证码。遇到验证、会话过期、访问受限立即停止对应操作。

首版限少量样本，不提供全站抓取、自动翻页到无限、自动发布、互动或导出完整用户主页。帖子被删除/不可见时保留失败记录，不能补造正文。

若实际后端不能稳定支持最小能力，网页里将该模式标为“准备中/不可用”，不得用模拟数据充当接通；可先独立发布网页研究里程碑，但不可宣称跨平台首版完成。

## 11. 获取、归一化与证据组织

### FR-11 统一来源记录（P0）

获取成功保存原文，保留原始格式并生成供分析的正文块。正文清理可移除导航和重复页脚，但不能覆盖原始快照。清理版本与原始哈希可关联。

各来源必须有稳定 source_id。当前原型按输入顺序编号，目标后台应在任务内首次分配后保持不变；增加来源不重排历史编号。

### FR-12 去重与来源关系（P0）

- 相同平台内容 ID 或规范化 URL 作为强重复信号。
- URL 规范化保留业务参数和必要访问参数；不能粗暴删除全部查询参数。
- 内容哈希相同可标记重复正文；不同网页转载相同内容标记为疑似同源。
- 同一厂商多个页面是多个文档，但不是多个独立主体；统计分别展示文档数、发布主体数和反馈作者样本数（可识别时）。
- 疑似重复不直接删除证据，保留关系并避免重复计数。

### FR-13 元数据与缺失值（P0）

发布日期、更新日期、采集日期分开。搜索引擎提供的日期标为候选元数据，不能自动视为原文确认的发布日期。

日期未知用 null；页面没有价格不等于价格为 0；没有发现处罚不等于无处罚；没有兼容列表不等于不兼容。

按时间范围筛选时，发布日期未知的来源单列“时间未确认”，不能静默计入近三个月统计。对指定日期政策有效性，另需核实适用时间及版本，首版不得仅凭发布日期推断。

### FR-14 证据片段（P0）

正文按段落或稳定行号生成 chunk_id。引用包含 source_id、chunk_id、短摘录和对应快照版本；长内容有截断时必须标识“本次仅处理部分内容”。

内容选择前去导航噪声，保留与子问题相关段落及必要上下文。超过上下文预算时不能只取前若干字符而声称已读全文。需要增加分段模型调用时纳入统一预算，首版优先降低每次获取数量。

### FR-15 证据集版本（P0）

每轮分析绑定不可变证据集版本，包含全部来源、URL、元数据、片段映射及内容哈希。复核结果必须匹配当前稿件与证据集。补查追加新版本，旧版可追溯。

哈希用于检查内容变化，不认证来源真实或抓取完整。外部文本一律作为待分析数据，不作为工具指令。

## 12. 分析与内容生成

### FR-16 主分析角色（P0）

输入：用户原始问题、确认后的意图、获取计划及执行摘要、当前证据集、已知缺口、输出模板。输出结构化报告，再由固定渲染器展示，不依赖模型自由输出 HTML。

重要结论至少包含：claim_id、文本、类型（来源陈述/事实转述/用户观点/模型推断/建议/未知）、证据引用、适用条件及关联子问题。是否重要的程序/人工评估规则见第 24 节，不把每个连接词都当结论。

证据不足时应明确说无法确认，不能以模型记忆填补并伪装成已获取来源。需要通用解释可单独标注“背景说明，未在本次检索中核验”，不得用于支撑业务关键判断。

### FR-17 通用研究输出（P0）

默认结构：直接回答 → 主要发现 → 逐项证据/比较 → 冲突或限制 → 待核实项 → 来源目录。简短问题不强制生成冗长研究报告。

比较任务必须对齐对象、版本、地区、时间及单位。缺字段显示未知，不能通过不同口径构造排名。价格、补贴等金额引用必须带币种、单位和条件；未获条件时只能列线索。

### FR-18 反馈分析输出（P0，依赖渠道）

结构：样本说明 → 主题分类 → 可定位的代表性表达 → 反例/相反体验 → 改进假设 → 下一步验证建议。

主题计数以已取得且去重的样本为分母；说明是笔记数还是评论数，不能混合。浏览量、点赞数、搜索排序不是用户规模。可展示“本次 8 条可用笔记中 3 条提到此问题”，不能表述为“37.5%的用户都有此问题”。

区分作者自述体验、转载、广告或身份不明内容。无法判断商业属性时标记未知，不凭语气断言刷评。只提取研究必要的内容，默认不导出个人联系方式等无关字段。

## 13. 独立复核 Subagent

### 13.1 产品定义

独立复核指使用独立模型调用和独立上下文检查草稿，不是在同一条回答里要求模型“再想一遍”。可与分析使用同一模型，但必须标明“独立调用”不等于“不同模型”或“独立事实来源”。

应用后台负责实际发起调用。当前 Codex 子助手只证明过交互原型流程，不能直接当成独立网页 API。

### FR-19 复核输入与输出（P0）

输入：问题及范围、稿件/证据集版本、结构化报告、重要结论、原文片段与足够上下文、失败来源和未完成子问题、剩余预算。不得传分析者隐藏推理或要求“证明前稿正确”。

输出：总体 verdict、逐结论检查、问题类型/严重程度、证据定位、建议动作、检查范围及限制。模型不计算或提供可信哈希；后台对实际发送的内容计算绑定信息，模型不能自行宣称匹配任意版本。

当前原型由子助手自行计算哈希；独立应用需要将该职责移到可信程序侧。

### 13.2 检查项

| 检查 | 需要发现的问题 | 示例 |
| --- | --- | --- |
| 支持关系 | 引用存在但不支持结论 | 一般维保多品牌 ≠ 智能服务全型号兼容 |
| 忠实转述 | 丢失限制、否定或归属 | “厂商称减少故障”被写成“已实测减少故障” |
| 数字与时间 | 数字、单位、分母和日期错配 | 采集时间当发布日期；笔记数当用户数 |
| 地区与实体 | 同名公司、市场或产品版本错误 | 全球服务描述替代中国开通条件 |
| 完整性 | 关键子问题遗漏或有明确合理补查线索 | 只回答监控而遗漏预测功能 |
| 冲突 | 不同资料版本不一致但被强行合并 | 两篇官网的服务条件不同 |
| 样本解释 | 评论事实化、过度概括或重复计数 | 三篇转载作为三份独立证据 |
| 内容边界 | 输出含无关个人信息或执行外部指令 | 网页要求上传密钥被当作操作命令 |

### FR-20 程序校验（P0）

程序检查 JSON schema、引用 ID 是否属于当前证据集、定位存在性、关键字段、版本一致性和停止规则。模型填写 unsupported 但总体 pass、引用未知来源等情况直接拒绝。

校验成功只证明结构和关联合法，不能代替语义复核。重要结论如果未包含在复核返回列表中，视为未检查，不能整体通过。

建议问题类型：unsupported、scope_overreach、wrong_date、wrong_entity、numeric_mismatch、citation_mismatch、missing_coverage、source_conflict、duplicate_count、format_error。严重度：blocking / nonblocking；blocking 必须修复、删除问题结论或明确转换为未知后重审。

## 14. Agent Loop 与停止条件

### FR-21 动作选择（P0）

| 复核问题 | 主助手可选择的动作 | 要求 |
| --- | --- | --- |
| 原文已有证据但表达错误 | rewrite | 改稿，记录改动及问题 ID |
| 合理范围内缺少证据 | fetch | 具体子问题＋查询/链接＋来源类型；通过工具与预算校验 |
| 获取文本不完整且后端允许重读 | reread（映射为 fetch） | 指明缺失内容，不重复获取完全相同内容消耗轮次 |
| 无可验证资料或已达到合理检索范围 | mark_unknown | 说明未知和本次范围，删除原来无依据的断言 |
| 必须用户提供信息/授权 | ask_user | 等待回复，不自动当作同意 |
| 已无可执行修正或达到上限 | stop | 输出待核实结果或无法完成原因 |

### 14.1 轮次规则

建议默认最多两次内容修正，对应最多三次复核；首轮分析不算修正。一轮可能包含小范围补查与改写，但都受获取总量上限约束。界面显示“修正 1/2”。

只有证据或稿件实际变化才进入下一复核版本。主助手不得直接改写子助手 verdict 为 pass。复核建议也是待执行数据，不能直接执行自由命令。

### 14.2 三种质量结果

1. **复核通过**：重要结论被检查且无未处理 blocking 问题；仍可包含合理标明的未知。
2. **未完全复核／仍有待处理问题**：达到上限、复核失败或关键项未检查。可展示草稿但明显标记，不能显示普通完成标记。
3. **无足够资料**：没有能够支持任务的有效证据，不调用分析模型编造报告，输出范围与失败摘要。

“任务部分完成”与“复核通过”可以同时成立：例如网页部分已核对，但用户指定的小红书来源缺失。两个维度分别保存。

### 14.3 什么时候可以停止搜索

已回答必要子问题，或合理检索范围已耗尽、剩余问题明确未知；不是要求把所有问题搜到肯定答案。复核不以无限补查为默认行为。

例：三篇中国官网没有型号兼容清单，系统可以交付“未确认全部型号兼容”，而不是持续换关键词直到找到可凑出的结论。

## 15. 模型、预算与资源边界

### 15.1 模型配置（供应商待确认）

首版建议单供应商，模型接入可替换；规划、分析、复核分别调用同一模型起步。配置记录供应商、模型请求名、供应商返回版本（如有）、提示词版本、关键参数、请求 ID 和用量。别名可能升级，因此不能仅依模型名声称完全可复现。

需要验证：中文理解、基于证据生成、工具/结构化输出、长上下文处理、延迟、费用、模型错误和服务可用性。使用兼容接口不代表不同供应商的参数、工具格式和思考计费完全一致。

### 15.2 建议首版默认上限（待 Q06，均可调整）

| 资源 | 建议默认 | 达限行为 |
| --- | --- | --- |
| 活动任务 | 1 个，额外任务不自动并发 | 提示等待或取消当前任务 |
| 每次搜索候选数 | 5 条 | 不继续无限翻页 |
| 单任务搜索请求 | 合计最多 6 次，含补查和失败尝试 | 停止搜索，说明范围 |
| 正文/详情请求 | 合计最多 24 次，含重试 | 不再读取新资料 |
| 成功来源 | 最多 12 份；首轮通常 3–5 份 | 优先相关与独立来源，不以凑数为目标 |
| 社区评论 | 默认不读取；能力验证后用户可开启，合计最多 30 条 | 明确样本有限和翻页覆盖 |
| 获取暂时性重试 | 默认 1 次，最高 2 次 | 原型已有实现；总请求预算仍累计 |
| 报告修正 | 默认 2 次，最高 2 次的标准模式 | 保留未知/转人工；高级放宽不在首版页面 |
| 模型请求次数 | 合计最多 12 次，含格式修复和失败重试 | 停止新调用，报告未完成原因 |
| 单次模型输入 | 目标最多约 24K token | 分块/减量，不静默截断关键证据 |
| 单次模型计费输出 | 建议上限 4K token，须核实供应商对思考 token 的规则 | 被截断输出不得直接视为有效结果 |
| 模型服务暂时性重试 | 每步最多 1 次，计入模型请求上限 | 无效密钥/欠费不重试 |
| 任务墙钟时长 | 建议 10 分钟，不含等待用户时间 | 停止发起新调用；保留已有记录 |
| API 单请求超时 | 建议 90 秒，接入实测后调整 | 明确可能已产生计费，不盲目重放 |

以上来源数、时间和 token 是资源约束，不是速度 SLA 或费用承诺。两次修正也不代表只调用两次模型。

### 15.3 费用展示与控制

输入、输出和缓存 token 分开累计；缺失时显示未知，不能填 0。费用估算注明供应商、价格版本、币种、缓存和思考口径，不在无依据时跨币种换算。

用户单次金额阈值在供应商确定后配置。发起请求前按已知输入和最大输出估计剩余预算；无法获得可靠计价上界时，只展示估算并依调用/token上限控制，不标注“保证不超支”。需要硬金额限制时先核实供应商预算功能及生效方式。

高于任务已有预算的扩展需用户明确同意；当前网页按钮提交任务只授权界面展示范围内的模型调用，不授权自动充值或开通新服务。

## 16. 信息架构与页面需求

### 16.1 导航

本机网页建议四个主要入口：新任务、历史任务、数据来源与工具、模型与运行设置。用户进入结果页后可返回历史，不要求注册账号。

### UI-01 新任务页

- 顶部：产品名称、实时/回放标识、模型和必要渠道是否准备好。
- 主输入：多行问题框，示例提示使用通用研究、反馈整理和指定链接三类。
- 可展开范围：地区、时间、来源限制、指定链接、输出形式、标准预算。
- 主按钮：“开始研究”；准备不充分时说明具体缺项并提供设置入口。
- 任务提交后显示已解析的范围、假设和计划；若需澄清，在同页回答，不丢原输入。
- 不默认给用户展示 token、MCP、CLI 等实现术语；费用和技术参数放可展开详情。

### UI-02 执行页

- 任务目标与范围固定显示，支持取消。
- 按真实事件展示：理解任务、制定计划、获取资料、分析、复核、补查/修正、交付。
- 显示获取成功/失败数量、当前正在做什么、已用时、修正次数。
- 使用阶段状态而非伪造完成百分比。未知时长不显示虚构剩余秒数。
- 获取记录可展开查看标题、平台、状态、采集时间和失败原因。
- 需要用户操作时显示阻塞原因、影响、可选项：“去本机处理”“跳过非必需来源”“取消”。不提供无授权的替代登录操作。

### UI-03 结果页

四个标签：回答/资料包、来源、复核记录、任务详情。

回答顶部依次显示任务范围、任务完成状态、复核状态和采集时间范围。正文中点击 [S1] 打开来源抽屉，定位对应片段。待核实项放在可见位置，不埋进长文结尾。

按钮：复制、导出、基于此任务继续。继续研究创建关联任务并展示复用的历史证据，不覆盖旧报告。

### UI-04 来源抽屉

展示标题、平台、内容类型、URL、发布日期状态、采集时间、原文片段、引用位置和处理范围。说明“保存的网页文本不等于完整网站内容”。允许打开原网址；原站内容已变化不覆盖本地历史快照。

### UI-05 复核记录

展示每轮发现的问题、严重度、涉及结论、对应证据、采取动作及结果。展示简明理由和工具动作，不展示或声称拥有模型隐藏思维链。人工错误演示标识与真实任务不同。

### UI-06 历史任务

列表字段：标题、创建时间、类型、完成状态、复核状态、耗时、来源数。可搜索标题、打开、复制、导出和删除。删除前展示范围，避免误删正在运行的任务；删除本地数据不表示撤回已发送给外部服务的数据。

### UI-07 工具与来源页

每个渠道展示：未接入/未配置/需登录/已安装未验证/最近验证可用/降级/失败。健康检查可能发起外部请求时提前说明。未接入渠道不可在计划中被执行；“计划支持”不显示成勾选成功。

### UI-08 设置页

模型供应商、模型名、密钥是否已配置、连接测试、预算、数据目录与数据管理。密钥不回显完整值；保存后 API 响应不得再次返回密钥。当前供应商未选择时呈现未配置状态。

| 状态 | 推荐文案 | 下一操作 |
| --- | --- | --- |
| 模型未配置 | “尚未配置模型服务，无法开始实时分析。你可以先查看样例。” | 去设置/查看回放 |

| 历史回放 | “这是已保存案例的回放，本次未执行实时搜索或模型调用。” | 开始新任务 |

### 16.3 基础体验要求

桌面浏览器优先，窄屏可读；控件可键盘操作，有明确焦点和标签；状态不能只用红绿颜色区分。长表格横向滚动，来源抽屉能返回原阅读位置。用户输入在短时刷新后保留，但密钥不存浏览器 localStorage。

## 17. 交付物与导出需求

### FR-22 回答模式

适用于问题有明确结论或少量子问题。优先直接回答，再给依据和限制。每个关键结论有来源引用；不要求所有结论都必须肯定，有证据限制的未知也是可用结果。

### FR-23 资料包模式

不是原文大合集，而是有结构的研究交付：

- 任务说明：问题、地域、时间、来源范围、采集时间。
- 摘要：主要发现和未解决问题。
- 结构化资料条目：主题/对象/要点/来源/证据/限制。
- 来源目录：成功、失败、未接入和排除情况。
- 复核摘要：轮次、主要问题、处理动作、当前状态。

同一次任务可从回答切换为资料包视图。仅改变布局/导出不重新调用模型；要求重新组织内容或新增分析时创建明确的新生成步骤并计费，不静默执行。

### FR-24 Markdown 导出（已确认 P0）

导出正文、任务范围、来源链接、关键短摘录、未知项和复核状态。相对本地文件路径不作为对外唯一引用，外部链接保留。导出文件名含任务简短标题和日期，避免覆盖。

未复核草稿导出顶部明确“未完成复核”，部分完成任务注明缺失来源；导出后的状态与网页一致。复制功能同样保留状态和引用。

### FR-25 CSV 导出（已确认 P0）

资料条目、来源列表分别导出 CSV，必要时另导出反馈主题表。采用 UTF-8（可加 BOM 以便表格软件识别），正确处理逗号、换行和引号。

推荐字段：item_id、topic、entity、claim_type、summary、source_ids、evidence_locators、published_at、fetched_at、limitations、review_status。

多值字段采用约定 JSON 字符串或分隔结构，说明格式。以 =、+、-、@ 等开头、可能被表格软件作为公式执行的外部文本要按安全导出规则处理，不能把平台内容变成可执行公式。

默认不导出完整网页全文、登录态、密钥和用户个人联系方式。原文留存在本机供核对；GitHub 发布使用审查过的最小例子。

## 18. 完整业务示例

### 18.1 案例 A：通用研究＋缺证据补查

**输入**：“通力预测性维保在中国提供哪些功能，是否所有型号适用？”

- 意图：产品功能研究；地域中国；来源偏好官网；回答模式。
- 获取计划：搜索中国官网，先读取产品说明，根据缺口补读服务资料。
- 初步分析：列参数采集、云端分析等功能，型号范围尚缺依据。
- 复核：发现预测功能说明不完整，要求补读两份已发现页面。
- 动作：取得新资料；区分一般多品牌维保与云管家的具体兼容性。
- 最终输出：有依据的功能清单；型号适用性未确认；附三份同厂商资料与限制。
- 停止原因：已完成合理范围补查，剩余兼容信息不能从当前来源推出，不无限搜索。

该案例已有助手驱动的真实记录，尚未由独立网页后台执行。

### 18.2 案例 B：官网＋小红书反馈（设计样例，未实测）

**输入**：“整理近三个月跑步 App A 的用户抱怨，结合官网功能提出改进机会。”

- 澄清：若 App A 为占位符或同名产品，先确认具体产品；将近三个月换算成明确起止日期。
- 计划：官网查现有功能，小红书搜用户体验，笔记正文为基础，评论能力未验证则不纳入。
- 获取：假设实际成功取得 5 条可用笔记（这里只举流程，不构造真实内容或成绩），按已知日期筛选并去重。
- 分析：归类体验问题，提供可定位表达；建议标为假设，不声称已经证明是产品缺陷。
- 复核：检查同源重复、时间范围、用户观点是否事实化、官网功能版本是否匹配。
- 交付：研究摘要和主题条目 CSV；标明样本是搜索获得的便利样本，不能推断市场占比。

### 18.3 案例 C：必要平台不可用

**输入**：“只根据小红书近一个月评论总结。”当前后端没有评论能力。

应输出：任务需要的评论能力不可用；可选择改为笔记正文研究或稍后接入评论。必须由用户同意改变来源范围，不能自动用网页摘要替代并正常标记完成。

### 18.4 案例 D：指定链接资料包

**输入**：“只根据这三个网页，整理功能比较表，导出资料。”其中一个 URL 404。

应输出：成功两个、失败一个；表格按现有证据组织，第三对象/维度为未知；保留失败链接和原因。若无法形成有意义的比较，应明确不足。外部增加第四来源需用户允许。

## 19. 任务状态与事件设计

### 19.1 三个状态维度

不要用单个“成功”覆盖所有情况。

| 维度 | 候选值 | 含义 |
| --- | --- | --- |
| execution_status | queued / running / waiting_user / completed / failed / cancelled / interrupted | 程序执行是否继续及终止原因 |
| coverage_status | full / partial / insufficient / unknown | 用户必要范围是否得到足够资料支持；full 仅针对约定范围，不表示全网查全 |
| review_status | pending / passed / unresolved / failed / not_run | 证据复核的完成情况 |

运行阶段 phase 可为 interpreting、planning、collecting、analyzing、reviewing、revising、exporting。阶段可以返回 collecting 以补查，不把任务误报为重启。

### 19.2 与现有 loop.py 的对应

| 当前状态 | 独立应用中的含义 |
| --- | --- |
| awaiting_review | running + reviewing + review pending |
| needs_revision | running + revising + review unresolved |
| passed | review passed；随后根据来源覆盖决定 completed/full 或 completed/partial |
| needs_human | unresolved；用户可明确继续/修改范围，否则保存部分结果并停止 |

当前 loop.py 没有完整 queued、waiting_user、取消、模型请求异常等状态；独立后台必须补齐，而不是修改显示文字当作功能完成。

### 19.3 事件日志

每条事件包含 task_id、event_id、时间、阶段、动作、状态、关联来源/稿件/复核 ID、次数和简短可公开说明。调用日志另记工具、参数摘要、耗时、错误分类与用量；凭据参数必须脱敏。

关键事件：task_created、clarification_requested、plan_created、source_fetch_started/finished/failed、draft_created、review_completed、revision_requested、budget_reached、user_cancelled、task_finished。

首版在本地持久化任务状态和版本文件。浏览器刷新从后台读取状态，不靠前端计时器猜进度。单任务只允许一个后台执行者更新版本；重复提交复核不得产生两次状态转换。

## 20. 数据对象与最小字段契约

本节用于明确模块交付内容，不规定必须采用特定数据库。字段带版本号以支持后续迁移。

| 对象 | 最小字段 | 约束 |
| --- | --- | --- |
| Task | id、schema_version、raw_input、intent、created_at、timezone、parent_task_id、mode、三类状态、limits | 原始输入不可被后续推理覆盖 |
| Plan | id、task_id、version、steps、assumptions、required_sources、budget_snapshot | 执行前必须通过工具/权限/预算检查 |
| ToolCapability | 第10节字段、adapter_version | 不含明文密钥 |
| ToolCall | id、task_id、capability_id、operation、redacted_args、start/end、status、attempt、error | 失败尝试仍记入预算 |
| Source | source_id、platform、source_type、url、canonical_id、title、publisher、author_ref、日期及其来源、fetched_at、status、error、raw_path、content_hash | author_ref按研究必要最小化；获取失败不能伪造content |
| EvidenceChunk | chunk_id、source_id、snapshot_id、text、locator、truncation_flag | 引用必须定位到本次快照 |
| EvidenceSet | id、version、source_refs、metadata_hash、content_hash | 新证据生成新版本，不覆盖 |
| Claim | claim_id、text、claim_type、scope、evidence_refs、uncertainties、subquestion_id | 不存在的引用不能进入通过结果 |
| Draft | id、revision、evidence_set_id、claims、report_structure、hash、prompt_version | 与送审版本严格一致 |
| Review | id、draft_id、evidence_set_id、model_call_id、checks、issues、verdict、limitations | 后台绑定输入版本；所有重要claim必须有检查 |
| RevisionAction | id、issue_ids、action_type、reason_summary、tool_call_ids、new_draft_id | 记录为什么补查/改写，避免无变化循环 |
| ModelCall | id、role、provider、requested_model、returned_model、parameters、prompt_version、input_hash、usage、elapsed、status | 无用量就null，不填0；不记录密钥 |
| Artifact | id、task_id、draft_id、format、path、created_at、disclosure_status | 草稿/部分完成标识随导出保留 |

### 20.1 证据引用例子（仅结构样例）

```json
{
  "claim_id": "C3",
  "text": "当前来源不足以确认所有型号均适用",
  "claim_type": "unknown",
  "evidence_refs": [{"source_id": "S2", "chunk_id": "S2-P12"}],
  "scope": {"region": "中国", "product": "示例服务"},
  "uncertainties": ["未取得型号兼容清单"]
}
```

这里的未知结论说明检索边界，不能把一段未提型号的文本解释为“不兼容的证据”。审查时既看引用，也看本次证据集覆盖和失败情况。

### 20.2 从原型迁移

保留已有 runs 下记录，不改写历史结论。旧记录可作为 legacy_import 显示，缺失字段标为未知。真实 API 后台运行与历史 Codex 代执行记录分开，不能把历史样例迁移后显示为应用自动完成。

## 21. 模块职责与建议接口

### 21.1 模块分工

| 模块 | 输入 | 输出 | 是否使用模型 |
| --- | --- | --- | --- |
| 网页前端 | 用户问题及设置操作 | 任务请求、结果展示 | 不直接调用供应商，不保存API密钥 |
| 任务调度器 | 任务、状态、预算 | 可执行步骤、阶段更新 | 控制逻辑由程序执行 |
| 意图/计划角色 | 问题、可用能力摘要 | 结构化意图与计划 | 是 |
| 工具适配层 | 已校验操作与参数 | 统一来源/失败记录 | 不需要模型来伪造结果 |
| 证据处理层 | 原始资料 | 去重、片段、证据版本 | 基础处理程序完成；额外模型调用必须显式计入 |
| 分析角色 | 问题、证据、输出模板 | 结构化草稿 | 是 |
| 复核角色 | 问题、草稿、证据 | 检查项和修正要求 | 独立模型调用 |
| 结果/导出层 | 校验后的报告与状态 | 网页、Markdown、CSV | 单纯渲染无需模型 |

建议继续复用 Python 获取与循环基础；具体前后端框架在技术设计阶段确定。PRD不将某个网页托管服务或框架自动当作用户已选方案。

### 21.2 本机接口契约建议

- 创建任务：返回 task_id 和初始状态，不长时间阻塞浏览器请求。
- 获取任务详情：返回范围、计划、阶段、覆盖和复核状态。
- 获取事件：按事件游标增量读取；轮询或服务端事件推送均可，首版选一种实现。
- 回答澄清：提交具体 question_id 的答案，检查当前是否仍等待该问题。
- 取消任务：幂等，只停止该任务，保留历史。
- 读取报告与来源：限该任务目录内资源，不能由传入路径任意读本地文件。
- 导出：绑定报告版本和状态，下载内容必须经过格式与路径校验。
- 能力检查与模型连接测试：单独操作、明确是否触发外部请求。

所有改变状态的接口按本机单用户设计，校验访问来源/会话，不因监听本机地址而完全放弃请求防护。

## 22. 异常、降级与恢复

| 情况 | 程序动作 | 用户看到什么 | 是否自动重试 |
| --- | --- | --- | --- |
| DNS/网络配置失败 | 记录network_error，停止该调用 | 网络或执行环境问题，不能判定平台不存在 | 默认否 |
| 超时/部分5xx | 按上限重试，计入总预算 | 正在重试/仍失败 | 有限 |
| 404/410 | 标记来源不可得 | 核对链接或页面已移除 | 否 |
| 401/403/明显登录页 | 标记需用户检查权限/会话 | 需要本机处理；403不直接等同未登录 | 否 |
| 429 | 停止对应服务的本轮新请求 | 限流，稍后再试 | 首版默认否 |
| 搜索仅有摘要 | 标为候选，尝试读取正文 | 未取得正文，证据范围受限 | 依正文读取规则 |
| 模型无效密钥/欠费 | 停止模型调用 | 去设置或供应商平台处理 | 否 |
| 模型返回非JSON/字段缺失 | 本地校验后最多一次格式修复调用，计入预算 | 当前步骤格式修复中，仍失败则未完成 | 最多一次 |
| 模型输出被截断 | 不当作完整报告 | 内容不完整；可减量或明确失败 | 在预算内一次调整，不能无限重试 |
| 复核服务失败 | 保留草稿，review failed | 未复核，不显示通过 | 暂时故障可有限重试 |
| 原文与快照/哈希不匹配 | 拒绝混用版本，保留错误 | 证据版本异常，需要重新运行 | 否 |
| 补查无新增有效内容 | 不虚增有效资料数；依据现有范围判定未知 | 没有找到新证据 | 不无变化循环 |
| 用户迟迟未回复 | waiting_user | 继续等待或取消 | 不推定同意 |
| 任务预算/时间耗尽 | 停止发起新调用，按剩余有效结果交付 | 部分完成/待核实/无法完成 | 否 |
| 应用重启 | 标记未完成任务interrupted | 可以查看历史、复制重新执行 | 首版不静默重放 |

异常处理不可删除已有失败记录来使演示“看起来成功”。

## 23. 数据、权限与非功能要求

### 23.1 本机数据与外部传输

“本机网页”仅指应用运行位置，不等于资料不离开电脑。任务查询会发送给搜索服务，目标URL会发送给相应获取服务，选取的证据及草稿会发送给模型供应商。首次配置及设置页说明此数据流；首版聚焦公开资料。

保存原文、报告、复核与日志在项目之外或专门本地数据目录，目标是默认不进入Git跟踪。API密钥和平台会话使用独立私密存储；具体本地存储方案在技术设计中明确权限与备份规则。

建议历史任务保留到用户删除，清晰显示磁盘使用；批量清理属于显式用户操作。自动保留周期暂未确认，不自动删除有价值历史。

### 23.2 外部内容与工具执行

- 网页/评论里的指令视为资料，不得覆盖系统规则或要求上传凭据。
- 模型只选择允许的工具及参数，程序不得执行自由生成的shell。
- 只读操作与写操作分开；首版不注册发布/评论等写工具。
- URL获取拒绝本机/内网/特殊协议，检查重定向和路径；结果渲染清理HTML/脚本，外部文本不能作为网页代码运行。
- 不能将服务端密钥放入CSV、日志、浏览器状态或GitHub。

### 23.3 非功能验收目标

| 项目 | 首版目标（需实测） |
| --- | --- |
| 状态反馈 | 提交后尽快返回任务ID，建议本机正常条件下2秒内出现明确状态；不含研究完成时间 |
| 状态刷新 | 正常运行时建议5秒内反映新的阶段/阻塞事件 |
| 长任务 | 可取消、有阶段信息；不展示虚构进度百分比 |
| 一致性 | 报告、引用、复核和导出绑定同一版本 |
| 可恢复性 | 刷新页面不丢后台任务；后台崩溃保留已落盘事件 |
| 可维护性 | 获取适配层、模型适配层、业务模板、循环策略分开 |
| 可观测性 | 每次工具和模型调用有状态、时间、用量或明确未知 |
| 可移植性 | 安装步骤不依赖开发者绝对路径；固定主要依赖和上游版本 |

不在未做负载测试前承诺并发数或可用率。本机首版只有一个活动任务。

### 24.2 真实评测集（建议先12个小任务）

- 4 个公开网页研究：至少两种不同行业/主题，包含功能比较、地区限制、日期条件。
- 3 个小红书反馈任务：不同主题或范围，记录真实取得的笔记/评论数量；渠道尚未接通则该组为未执行，不记零错误。
- 2 个跨平台任务：官网功能与用户体验结合，检查观点归属和证据口径。
- 3 个不足/失败任务：必要来源不可用、指定链接失败、找不到直接支持的结论。

另设人工错误集和模拟故障集，分别验证复核机制和工程分支，不与真实回答混算。

### 24.3 人工标注规则

关键结论包括会影响用户判断的功能、金额、数量、日期、地区、适用范围、排名及“所有/没有/一定”等断言。由刘子谦或指定评审人逐条对照来源，记录 supported / unsupported / partially_supported / cannot_judge。

出处正确与事实真实分开评价；厂商宣传被准确转述可以 supported，但不能因此认定宣传的实测效果真实。无法判断的样本不得硬归为正确。

### 24.4 对照实验

设 A 为同一证据集直接总结，B 为同模型同证据的总结＋复核修正。固定输入和基础预算，记录错误、遗漏、人工核对时间和模型用量。若 B 允许额外补查，另作为 C 条件报告新增来源及成本，不能把数据量差异全部归功于复核。

首轮12题仅能发现明显问题，不能支持总体统计结论。每条结果报告样本数和未判定项；若尚无人工标注，不发布准确率。

### 24.5 发布阻断条件

只要存在可复现的以下问题，不能发布为“可正常使用”的实时首版：泄露密钥；未配置渠道显示可用；执行任意模型shell；把失败正文当证据；没有复核也显示通过；超过预算继续无上限调用；版本混用导致错误引用；回放冒充实时。

一般体验缺陷可在限制清单中说明。若小红书尚未验收，可发布明确命名的“网页研究预览版”，但不能宣称目标跨平台首版完成。

## 26. GitHub作品与风险管理

### 26.1 仓库内容

建议包含：README快速理解与运行、PRD、架构与工作流说明、程序源码、锁定依赖、配置样例（无密钥）、少量可公开样例、测试、评测方法与结果、版本说明、上游致谢与许可处理。

### 26.2 演示要求

演示一次正常研究、一次真实补查、一次明确停止。展示用户输入、来源和复核动作；事先准备的回放用标签说明。不要把人工错误测试讲成真实用户任务发生过的错误，也不要把当前主助手执行截图当作独立后台运行证明。

### 26.3 风险与处理

| 风险 | 影响 | 首版处理 |
| --- | --- | --- |

### 28.1 原型状态与目标状态差异

现在：用户在Codex提问 → 当前主助手选工具并执行 → 当前子助手复核 → 本地脚本存记录。

目标：用户在本机网页提问 → 本机后台自动规划和执行 → 模型API分别完成分析与复核 → 程序按约束决定循环和停止 → 网页与导出展示可追溯结果。

目标完成必须以后一条链实际运行证明，不能只将已有JSON放入页面。

# 课程演示脚本（约 5 分钟）

## 1. 先讲产品边界（30 秒）

这是一个面向产品经理和个人研究者的资料研究助手。用户提出问题后，程序根据意图调用公开资料获取能力，再由分析角色整理，独立复核角色检查证据边界，必要时只允许一次修正。

首版只验收公开网页；小红书、多平台并行和 UI 美化仍是后续工作。电梯行业是测试案例，不代表产品只服务电梯行业。

## 2. 展示本机网页（60 秒）

启动：

```sh
.venv/bin/python research_web.py --port 0
```

在页面输入：

> 电梯行业预测性维保的公开资料有哪些？

选择地区“中国大陆”、时间“2026”、来源“公开网页”，先查看计划预览。

说明每一步负责人：程序负责计划和状态，Exa 负责候选搜索，Agent-Reach/Jina 负责读取网页，模型角色负责分析和复核。

## 3. 展示证据而不是只看答案（60 秒）

点击获取公开网页，再点击准备分析资料。展示 S1、S2、S3 的网址、采集时间、正文哈希和范围限制。

强调：网页正文中的命令不是授权；采集成功不等于事实已经核实；地区、日期和适用范围未知时会保留为未知。

## 4. 展示复合 Agent loop（90 秒）

用离线回放入口展示固定流程：

```text
分析草稿 → 本地引用校验 → 独立复核
                         ├─ pass → 交付
                         ├─ revise → 修正一次 → 再复核
                         └─ fetch/预算不足 → 停止并保留记录
```

指出独立复核不读取分析者的对话历史，只接收问题、证据、草稿和复核目标。每个版本有独立哈希，不能把未通过草稿标成最终报告。

## 5. 展示真实验收结果（60 秒）

打开：

- [首版真实验收](../runs/mvp-elevator-2026-09-24/RESULT.md)
- [官方补充资料真实结果](../runs/public-web-elevator-followup-2026-09-24/MODEL-RESULT.md)

说明真实结果最终是 `revise`，不是预先写好的“90% 准确率”。复核确实发现了引用扩大、样本外推和政策适用范围问题，程序因此停止。

## 6. 最后讲下一步（40 秒）

下一步是把脱敏结果接入结果页，再接入小红书用户反馈；需要登录时由用户在本机完成，不在聊天中传密码或 Cookie。GitHub 发布只提交代码、测试、PRD 和脱敏摘要，不提交本机凭据、整页网页正文或模型原始响应。

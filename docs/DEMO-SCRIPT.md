# 课程演示脚本（约5分钟；方案 A）

本脚本对应 `research_web.py` 默认工作台。优先展示本机已有真实记录，查看历史、原文和导出均不新增模型调用。GitHub下载者不会得到本机历史或凭据，可阅读脱敏验收摘要，或运行明确标注的离线回放。

## 1. 产品定位（30秒）

“这是一款面向产品经理／个人研究者的资料助手。用户提出问题，程序从已接入来源获取证据，由分析模型整理、独立复核模型检查，必要时有限修正，输出回答和资料包。”

通用研究是方向，电梯问题是当前案例。来源中心预留15个入口，目前只有公开网页可执行，小红书后续接入。

## 2. 主界面与操作（50秒）

按 [启动说明](QUICKSTART.md) 打开本机页面。左侧为研究历史和来源中心，中间为需求与进度，右侧为报告、来源、过程与复核。

示例问题：“通力中国官网如何描述预测性维保的功能？哪些型号或地区适用条件尚未明确？”

展示新建研究的输入、范围与来源选择，但无需现场提交。提交后正常阶段自动推进，无需逐阶段点击继续；这会真实调用模型。当前限制标为“开发验收配置”，不是永久产品套餐。

## 3. 展示真实报告与证据（80秒）

在本机研究历史中打开2026-09-26 16:41的已结束任务（当前机器为北京时间）。核对报告标记“本轮复核未发现问题”，以及1项已回答、1项明确未知、1项待验证假设。

点击一处“查看引文”：展示来源网址、采集时间与保存的原文片段。3份资料均来自通力中国官网，但采集时间不能代替发布日期，官网功能描述也不等于设备性能经过独立实测。

用具体例子解释边界：“一般维保支持多品牌，不足以证明云管家兼容所有品牌；报告保留型号、地区、日期等未知项。”假设单独标注，不能当事实。

## 4. 展示 Agent loop 与失败记录（70秒）

打开“过程与复核”：先前DeepSeek要求补充一项限制，Qwen据此修正，新的DeepSeek复核返回pass；继承意见与新复核分开展示，草稿和证据版本绑定。

程序负责调度、校验、预算和停止；Exa负责搜索，Agent-Reach/Jina负责读取。这份历史案例由Qwen分析/修正、DeepSeek复核；现在新任务默认Qwen Flash分析/修正＋Flash思考复核，旧案例未迁移。

如实说明本案例跨多个任务完成：早期引用/定位失败、一次网络请求失败均保留，新版5次阶段预算才解决后续同类流程容易差一步的问题；不能把此次历史说成一次点击就完全无故障成功。通过的是本案例对保存证据的模型复核，不是整体准确率或90%准确率。

## 5. 导出与继续研究（50秒）

点击Markdown和CSV导出，说明网页与导出使用同一结构化结果，包含结论、未知、来源和状态。“编辑补充需求”先打开编辑页，最终点击“开始研究”才创建关联任务，不覆盖旧报告。

如需演示停止分支，可查看已有失败历史。旧版工作台提供固定虚构输入的离线回放，必须说明“模拟”，不与真实案例混用。

## 6. 收尾（20秒）

“公开网页已有历史闭环案例，当前交付研究辅助预览版，稳定语义质量仍未通过。新增Zotero网页任务因修正格式失败停止，证据和草稿保留；不得包装成成功案例。下一步收集试用反馈，再逐步接入小红书。当前按开发验收配置运行，正式研究档位和用户日费用上限属于后续规划。”

# 简化复核与限制说明检查：固定验证

本轮只处理首版收尾清单第1项的复核质量，不增加平台、不启用Max、不自动替换网页默认配置。程序交付和质量验收分别记录。

## 执行前固定的改动与判定

引用使用完整原文片段目录；复核模型只填写目标ID、支持与否、理由、证据编号，程序派生重复字段，不替模型作语义判断。回答A、假设H、限制说明L均必须逐项覆盖。通用词语匹配给出定位及邻段导航，完整来源仍保留，导航不包含人工标准答案。

限制说明允许在原位置修改，保留版本与目标ID；修改或反驳都须提供依据，之后独立再复核。旧结果与literal、segments-v1契约不迁移。新模式名为compact-v2，暂由后台显式启用。

固定模型配置为qwen-review-thinking-json-v2：分析、修正用Qwen3.8-Flash非思考；复核用同款思考4096、总输出8192，独立上下文、JSON Object、SSE。观察下列实测响应后不改提示词再重复同题。

### 这轮确认了什么

1. 减少模型重复填字段确实消除了本轮原有契约失败，但这里只是5个案例，不能宣称长期稳定。
2. 限制说明已进入程序检查范围；“检查到了”不等于“判对了”。Bitwarden错误不是漏交L字段，而是复核员接受了缺少充分前提的推论。
3. VS Code没有因预算或接口失败停止，实际完成复核后仍漏检。因此目前阻碍是这套模型、提示词与证据组织下的语义可靠性，不能再归因于登录或字段格式。
   进一步检查输入：明确描述语言特定用户设置例外的段落在完整来源内，但未进入Q2词语导航前列；导航包含了优先级表，却仍偏向草稿已有引用。因此不能把结果简单归因于模型参数规模，证据导航和任务拆分也仍有改进空间。
4. 一般官方文档题可以低成本完成，但复杂条件与证据不足推论仍需人工核对。本轮没有比较新模型，不能证明换Max就能解决，也不支持把Max设为默认刚需。
5. 一次修正→再复核在模拟集成测试中通过，包含L目标修改、版本保留和原文绑定；本轮真实旧稿因漏检未触发修正。两者不能混称“真实修正链验收通过”。
